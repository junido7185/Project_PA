작성: 2026-09-07. 범위: 상세 검토, 제작 명세, 첫 작업 지시서. **이번 작업은 문서 설계이며 Unity 구현 착수가 아니다.**

사용자 구상은 채택할 방향으로 구체화하되, 인원·비용·체험 시간 등 새 수치는 제작용 제안이다. 기존 캐논과 CONTENT-002 활성 상태, CONTENT-000B~010 선승인 기록을 이 문서로 변경하지 않는다.

## 1. 판단

**이미 완성된 마을로 되돌아갈 필요는 없다. 플레이어가 직접 정착지를 정하고, 함께 온 주민이 처음 공급할 상품을 결정하는 시작은 기존 잡화점 게임과 잘 맞는다.**

다만 기능을 모두 합쳤다는 사실만으로 창의성이 생기지는 않는다. 이 게임의 중심은 다음 인과관계다.

> 내가 함께 살 사람을 고른다 → 그 사람과 확보한 물건을 내 가게에 판다 → 산 주민이 물건을 사용한다 → 내가 자리 잡은 섬의 모습과 생활이 바뀐다.

동행 선택·본사 기술 전수·항구 개폐는 이 관계를 돕는 수단이다. 플레이어는 섬에 실제로 살며 낮에는 생활과 개발, 밤에는 잡화점을 맡는다. 전체 인력을 위에서 명령하는 도시 경영자로 옮겨가면 기존 정체성의 장점이 약해진다.

데모 우선순위는 **첫 정착 → 첫 판매 → 다음 날 눈에 보이는 주민 반응**이다. 관광객 유입 토글은 기존 코드 재사용 여지가 있어 후순위의 작은 기능으로 가능하다. 정기선 시뮬레이션·항구 증축·호텔·과학 시설까지 한꺼번에 넣는 것은 현재 데모에 과하다.

## 2. 비교 게임에서 가져올 원리와 P.A.의 차이

아래 원작 설명은 개발사·배급사·플랫폼의 공식 소개를 근거로 한다. 오른쪽은 그 자료와 사용자 구상에 대한 설계 판단이며, 법적 비침해 판정이 아니다.

| 비교 대상 | 실제로 겹치는 경험 | P.A.가 전면에 보여줄 경험 |
|---|---|---|
| 동물의 숲 | 무인도 생활, 동물 이웃, 텐트·휴대폰·제작, 섬 꾸미기 | 주민은 내 물건의 생산자이면서 구매자·사용자. 판매가 다음 날 생활과 풍경에 남음 |
| 딩컴 | 채집·농사·낚시와 자유로운 마을 배치 | 첫 동행 조합이 초기 공급과 상품 구성을 바꾸고, 같은 자원을 판매·기술·건설에 배분 |
| 스타듀 밸리 | 생활 일정, 농업, 인물과의 관계 | 이미 있는 마을을 알아가는 방식에서 출발하지 않고, 주민과 살 장소·상업의 시작을 함께 정함 |
| 문라이터 | 직접 진열하고 가격을 정하는 상점 운영 | 섬 주민이 공급한 자원이 다시 주민 생활로 돌아옴. 외부 탐험 전리품이 주된 공급원인 구조와 다름 |
| 고고타운 | 방문객을 받아 마을 상업을 키우고 생산·일자리를 연결 | 주민과의 생활을 기본으로 유지하며, 관광객 방문을 받을 시기를 플레이어가 선택 |

근거: [Nintendo — 동물의 숲](https://www.nintendo.com/en-gb/Games/Nintendo-Switch-games/Animal-Crossing-New-Horizons-1438623.html), [Nintendo — Dinkum](https://www.nintendo.com/us/store/products/dinkum-switch/), [Stardew Valley 공식 소개](https://www.stardewvalley.net/about/), [Moonlighter 배급 소개](https://store.steampowered.com/app/606150/Moonlighter/), [Go-Go Town! 배급 소개](https://store.steampowered.com/app/2195120/GoGo_Town/).

위 표는 각 작품에 P.A.의 요소가 전혀 없다고 주장하지 않는다. 시장 전체의 최초성을 입증한 조사도 아니다. **데모를 본 사람이 기억할 중심 경험을 어디에 둘 것인가**에 대한 비교다. 고고타운의 구체적인 열차 게이트 규칙과 동일하다고 확인한 것은 아니며, 항구 규칙은 이번 게임의 제안으로 아래에서 정의한다.

## 3. 창의성을 실제 플레이로 만드는 보완

### 3.1 직업 대신 사람을 고르게 한다

직업 카드에 생산량만 적으면 최적 조합 계산으로 끝난다. 각 후보는 `첫 공급 품목 / 섬에서 하고 싶은 일 / 좋아하는 생활 장소`를 한 줄씩 가진다. 성격과 희망은 대사·방 배치·일과에 쓰고, 별도 복잡한 적성 수치를 추가하지 않는다.

예: 목재 생산자는 작업 후 텐트 밖에서 물건을 손질하고 싶어 한다. 어업 주민은 낮에 잡은 생선으로 저녁을 함께 먹고 싶어 한다. 곤충 채집가는 숲 가장자리의 관찰 공간을 원한다. 이는 새 캐릭터의 확정 설정이 아닌 역할별 연출 예시다. 기존 이름과 직업을 문서 승인 없이 바꾸지 않는다.

### 3.2 첫 판매의 결과를 주민에게 돌려준다

첫 손님은 누구인지 알 수 있는 동행 주민이다. 실제 거래가 성공한 뒤에만 그 주민의 생활 소품이나 행동이 바뀐다. 영업 통계 화면만으로 끝내지 않는다.

가구 제작은 기존 Tier 2 조건이 있어 첫날에 억지로 주지 않는다. 초반에는 원재료 꾸러미, 식사 자리, 정리된 텐트 앞처럼 해당 판매품으로 납득할 수 있는 작은 변화를 쓴다. 목재를 팔았는데 다음 날 완성 가구가 공짜로 생기는 연결은 피한다. 규모 있는 변화는 가공품 판매가 가능해진 뒤로 둔다.

### 3.3 기술은 자원의 새 쓰임을 연다

나무를 본사에 제출해 나무를 처음 얻는 기술을 배우게 하면 막힌다. 입주가 기본 분야 접근을 열고, 본사 제출은 그 위의 정리·가공·응용을 연다. 첫 기술마다 새 상품, 새 작업 또는 확인 가능한 보관·진열 변화가 있어야 한다. 단순 생산량 +5% 노드를 잔뜩 늘리지 않는다.

기술 화면에는 현재 선택한 분야와 다음 두 단계 정도를 먼저 보여준다. 첨부 이미지에서는 개별 노드의 내용과 출처를 판독할 수 없어, 연결된 기술망이라는 구조만 참고한다. 아이콘·선의 배치·색·단계 순서를 그대로 가져오지 않는다.

### 3.4 초반의 작은 가게가 후반의 섬 특화로 이어진다

관광 특화는 숙박객 숫자를 별도로 키우는 데서 끝나지 않고, 주민이 만든 식품·가구·기념품의 새 수요가 된다. 과학 특화는 광물·곤충·작물의 관찰용품과 조사 의뢰가 새 수요가 된다. 상점이 커진 결과로 섬에 어떤 사람이 오는지가 바뀌어야 한다.

후반에는 하나만 영구 선택하는 직업 분기보다, 투자 비중에 따른 주력 분야와 다른 분야의 공존을 권한다. 곤충을 선택한 플레이어에게만 과학 엔딩을 주거나 어업을 선택하지 않으면 관광을 못 하게 하는 잠금은 만들지 않는다.

## 4. 저작권과 표현상 유사성

### 4.1 아이디어와 표현을 구분하되, 조합도 살핀다

한국 대법원은 게임의 구체적인 창작적 표현을 비교하며, 요소의 선택·배열·유기적인 조합에서 생기는 창작적 개성도 고려한다. 따라서 ‘판매·무인도·기술 트리는 아이디어이므로 어떤 조합도 안전하다’거나 ‘그림만 바꾸면 된다’고 결론 내릴 수 없다. 이 판결은 다른 장르의 개별 사건으로, 현재 P.A.의 침해 여부를 직접 판정하는 자료는 아니다. [대법원 2019. 6. 27. 선고 2017다212095](https://law.go.kr/LSW/precInfoP.do?precSeq=208504).

지금은 기획 문장과 일부 구현을 검토한 단계다. 최종 화면·캐릭터·음악·대사·진행 연출 전체를 비교하지 않았으므로 비침해 보증이나 수치화한 법적 위험 점수를 제시하지 않는다. 배포 국가별 법과 상표·특허 문제는 별도의 검토 대상이다. 게임에는 여러 종류의 지식재산권이 함께 적용될 수 있다. [WIPO — Video Games and IP](https://www.wipo.int/en/web/wipo-magazine/articles/video-games-and-ip-a-global-perspective-38773).

### 4.2 가장 조심할 부분은 시작 장면의 묶음이다

**본사 안내 → 동물 주민과 무인도 → 텐트 설치 → 휴대폰으로 생활 확장**은 동물의 숲을 연상시킬 가능성이 크다. 이는 위 공식 소개와 대조한 디자인 판단이며 법적 결론은 아니다. 비행기를 배로 바꾸는 것만으로 인상이 충분히 달라지지는 않는다.

구체적인 대응은 다음과 같다.

| 부분 | 제작 방향 |
|---|---|
| 본사 | 리조트 접수대보다 물건을 싸고 진열을 연습하는 항구 출항 작업장. 본사는 교육·물류 파트너로 표현 |
| 출발 이유 | 섬 여행 패키지나 대출 계약보다 자기 가게를 꾸리려는 선택과 동행자의 생활 계획 |
| 첫 행동 | 주민 설명을 오래 듣기보다 실제 상품과 가격표를 만지고, 동행할 사람의 일을 살펴봄 |
| 상징·화면 | 프로젝트 미술 문법의 재질·팔레트와 자체 송장·가격표·물류 도장. 기존 게임의 나뭇잎 상징, 특징적인 서체·앱 배열·말풍선·효과음 모사 금지 |
| 주민 | 동물 종만 바꾸는 방식보다 다른 얼굴 비례·실루엣·의상·행동·대사. 캐릭터 시트와 제작 이력 유지 |
| 기술 화면 | 실제 공급품과 본사 전수 과정을 읽을 수 있는 자체 구성. 첨부 그래프의 좌표·아이콘·연출 복사 금지 |

이 조치는 디자인을 독립적으로 만드는 작업이며 법적 안전을 자동 보장하는 체크리스트는 아니다. 비교 작품 이름은 내부 기획 참고로 사용하고, 공개 소개는 P.A.의 플레이 경험으로 쓴다.

### 4.3 현재 자산에서 확인할 부분

`Docs/AssetProvenance/EXTERNAL_ASSET_REGISTRY.md`에는 CC0 외부 팩의 입고·출처 기록이 있다. 개별 사용 자산의 원본과 라이선스가 연결되는지 최종 빌드 기준으로 확인한다. 예를 들어 Kenney Mini Market은 공식 페이지에서 CC0로 표시한다. 이것이 다른 모델·폰트·음악까지 확인해 주지는 않는다. [Kenney Mini Market](https://kenney.nl/assets/mini-market).

`Docs/Codex/TRIPO_ASSET_AUDIT.md`의 FroggyChair는 런타임 사용 제거 기록과 원본/Resources 잔존을 구분해야 한다. 이번 작업에서는 삭제하거나 빌드 포함 여부를 판정하지 않았다. 생성형 자산은 생성 당시 서비스 조건, 요금제와 생성 이력, 입력 이미지의 권리를 함께 기록해야 한다. 서비스의 상업적 이용 허용이 제3자 입력물의 권리나 결과의 비침해를 보장하지는 않는다. [Tripo 이용약관](https://www.tripo3d.ai/terms).

게임명·로고의 상표 검색, 특허 조사, 모든 외부 자산의 배포 허용 여부는 이번에 확인 못 했다. 출시용 권리 검토는 최종 배포물과 증빙을 대상으로 한다.

## 5. 완성도를 해칠 수 있는 빈틈

| 빈틈 | 플레이 중 생기는 문제 | 보완 기준 |
|---|---|---|
| 목재 직업이 사실상 필수 | 다른 조합은 집도 못 지음 | 거점 1개·주민 텐트 2개 설치 키트와 공통 기초 활동을 무료 제공 |
| 입주·기술·고용 혼동 | 사람을 샀는데 일을 안 한다고 느낌 | 입주=함께 생활, 기술=플레이어 능력, 고용=유료 작업 위임으로 따로 설명 |
| 도구를 얻으려면 해당 자원 필요 | 순환 잠금 | 기본 도구·분야 접근은 입주 시 제공. 본사 제출은 다음 단계만 요구 |
| 농사만 대기 시간이 김 | 농업 조합의 첫날이 비어 있음 | 출항용 수확물 소량과 재배 실습 분리. 정상 성장 시간을 계속 건너뛰지 않음 |
| 곤충 분야의 구매 이유 부재 | 잡아도 팔 이유가 없거나 과학 전용 재료로 고립 | 관찰 세트 등 생활 수요를 먼저 정의. 곤충·채집·상품 기능의 실제 제작 비용 포함 |
| 모든 돈을 입주에 사용 | 판매할 재고나 고용비가 없어짐 | 공통 수동 채집·판매는 비용 0으로 재개 가능. 첫 두 주민의 입주비는 출항 지원에 포함 |
| 주민을 직원으로만 취급 | 동물 마을의 관계성이 약해짐 | 계약이 없어도 일과·대화·소비가 있고, 계약 종료 후에도 집과 배운 기술은 유지 |
| 확률적 첫 판매가 지연 | 튜토리얼 진행이 멈춤 | 첫 판단과 첫 판매를 구분. 재가격·다음 손님 안내, 거절해도 재고 보존. 거래 성공 강제 금지 |
| 아무 물건이나 사고 같은 장식 생성 | 핵심 차별성이 가짜로 느낌 | 거래의 주민 ID·상품·수량과 변화의 근거를 연결하고, 해당 품목에 맞는 결과만 생성 |
| 항구가 닫히면 수입 0 | 성장에 집중할 선택이 손해가 됨 | 주민의 밤 구매·생산·본사 연락·지원 수송은 유지. 관광객은 추가 수요 |
| 항구를 열어두는 것이 항상 우월 | 토글이 의미 없는 버튼 | 더 많은 재고 소진·재진열과 방문 활동이 늘어나는 차이를 측정. 억지 입장료나 불만 벌점은 추가하지 않음 |
| 자유 배치가 길을 막음 | NPC가 집·상점에 못 감 | 배치 전에 진입점·상호작용 면·상점까지 경로 확인, 초기 이전 부담 최소화 |
| 해금망만 커짐 | 상점보다 제출 업무를 오래 함 | 첫 기술의 제출량은 짧은 공급 주기 안에서 마련; 다음날 새 물건/행동을 확인 |
| 조합별 별도 장편 도입 | 대사·회귀 검증 규모 급증 | 공통 단계와 역할별 짧은 대사 슬롯 사용. 필요한 등장인물은 사건 조건으로 연결 |

## 6. 경제 데이터에서 확인한 것

2026-09-07 작업 트리의 `Assets/Resources/Items`, `Production`, `Recipes`를 직접 읽었다. 아래는 품질·가격 설정·노동·판매 확률을 적용하기 전의 **기준가 비교**다. 실제 수익 측정 결과가 아니다.

| 원재료 | 아이템 기준가 | 생산 데이터 납품 단가 | 같은 기준가로 재판매 시 단위 차액 |
|---|---:|---:|---:|
| 나무 | 8 | 8 | 0 |
| 광물 | 15 | 15 | 0 |
| 생선 | 18 | 18 | 0 |
| 밀 | 10 | 10 | 0 |

| 가공품 | 실제 레시피 | 재료 기준가 합 | 산출물 기준가 합 | 단순 차액 |
|---|---|---:|---:|---:|
| 판자 | 나무 2 → 판자 1 | 16 | 25 | 9 |
| 철괴 | 광물 2 → 철괴 1 | 30 | 40 | 10 |
| 빵 | 밀 3 → 빵 1 | 30 | 30 | 0 |
| 생선구이 | 생선 1 → 생선구이 1 | 18 | 52 | 34 |

출력 품질은 판자·철괴·빵 1.2, 생선구이 1.26을 기본값으로 갖고 재료 품질도 반영한다. 따라서 표의 차액만으로 최종 수익을 단정할 수 없다. 하지만 같은 물건을 납품받아 파는 재미와 직업 간 차이를 점검할 충분한 근거다. 재료·상품 이름도 확인해야 한다. 현재 구운 감자 레시피의 입력은 당근이며 의류에는 밀·판자가 들어간다. 콘텐츠 전환 때 임시 조합을 의도된 상품으로 정리할 대상이다.

구매는 `PurchaseEvaluator`의 품질 반영 이상가 대비 진열가, 카테고리 선호·가격 민감도·성향, 난수로 결정된다. 별도의 누적 ‘만족도 점수’가 현재 평가식에 존재한다고 보고하지 않는다. 사용자 표현의 만족도는 우선 기존 판단을 표정·말풍선·구매/거절로 이해시키는 데 사용한다.

밸런스 작업에서는 `영업 종료 현금 변화`, `남은 재고 원가`, `직접 작업 시간`, `본사 제출로 포기한 판매 기회`, `실제 구매 전환율`을 따로 측정한다. 재고를 유지하는 게임에서 매 방문의 이익을 단순히 `(판매가−원가)×확률`로만 계산하면 미판매 재고와 회전 시간을 놓친다.

첫 조정 후보는 원재료 도매 마진과 빵의 가공 보상이다. 임의로 모든 가격을 올리지 않는다. 같은 시드·같은 손님 조건에서 각 시작 조합의 첫 수입/첫 기술/재고 보충 가능성을 비교한 뒤 별도 밸런스 티켓에서 조정한다. 수치 초안과 통과 목표는 제작 명세 §8을 따른다.

## 7. 데모와 장기 개발의 경계

권장하는 첫 완성 단위는 **약 20~30분, 2~3일의 정착 체험**이다. 이는 측정 전 시간 목표이며 승인된 첫 달 캠페인을 폐기하거나 자동 축소하는 결정이 아니다. 짧은 구간을 먼저 검증한 뒤 기존 첫 달 목표에 연결한다.

| 우선순위 | 범위 | 완료 증거 |
|---|---|---|
| P0 | 짧은 본사 실습, 동행 선택, 출항·도착 | 선택한 주민이 실제로 함께 도착하고 시작 안내가 일치 |
| P0 | 거점/텐트 직접 배치, 기초 공급, 실제 상점 진열·가격·구매 | 다른 시작 조합에서도 강제 직업 없이 첫 거래 가능 |
| P0 | 첫 본사 기술 1개, 실제 판매에 따른 생활 변화 1개 | 자원 소모와 해금이 저장되고, 주민의 변화가 화면에 보임 |
| P0 | 입주한 동일 주민의 유료 고용 1회 | 새 복제 NPC 없이 계약과 작업 결과가 이어짐 |
| P0 | 저장·재시작·첫 경험의 가독성 | 위치·주민·재고·거래 결과 보존, 전체 체험 완주 |
| P1 | 관광객 방문 허용 토글 | 닫아도 주민 경제 유지, 열면 기존 임시 손님 추가, 한도 우회 없음 |
| 후속 | 정기선 운항, 항구 증축, 여러 가공 직업, 호텔·연구 시설, 큰 기술망 | 기존 공급·판매·주민 루프에 새 수요로 연결 |

사용자가 생각한 후보 5직업은 설계 목표로 보존한다. 현재 데이터 재사용이 가능한 기본 생산은 목재·광물·어업·농업 4종이고 곤충 분야는 새 제작이 필요하다. 내부 검증은 기존 4종의 6조합으로 시작할 수 있지만, 이를 곧바로 공개 데모의 확정 후보 수로 바꾸지 않는다. 공개 데모가 5종을 약속하면 곤충 경로와 총 10조합 검증까지 P0다.

## 8. 현재 개발에 적용할 때의 충돌

`Docs/PROJECT_STATE.md`는 8월 25일 기준으로 최신 진행을 모두 담지 못한다. CONTENT-001은 기존 로그상 검증 완료이며, 현재 CONTENT-002는 실제 입력 관련 교정 체크포인트가 남은 상태다. 이번에는 그 검증을 재실행하지 않았다.

| 현행 구현/문서 | 새 구상과 부딪치는 부분 | 후속 처리 |
|---|---|---|
| WorldGameplayAdapterService의 기본 시설 생성 | 무인도인데 상점·작업 시설이 먼저 있음 | 신규 캠페인에만 설치 전 상태를 두고, 기존 회귀/로드 경로 유지 |
| CampaignOpeningController의 보리 전제 | 선택하지 않은 주민이 첫 이웃으로 고정됨 | 인사·첫 거래 역할을 선택한 resident ID에 연결; 보리 캐논 배역은 별도 정리 |
| HiringService의 Instantiate | 이미 입주한 인물이 고용 때 복제될 수 있음 | 입주 객체와 계약을 동일 ID로 연결하는 기존 계획과 통합 |
| 기존 Tier/시설 레시피 | 직업 기술이 기존 제한을 무단 우회할 수 있음 | 해금 조건을 추가하되 필요한 Tier/시설 변경은 별도 명시 |
| CustomerArrivalController | 관광객은 이미 있으나 항구와 연결되지 않음 | 기존 임시 관광객 유입 지점에 허용 조건 추가; 주민 초대와 분리 |
| 기존 SaveData/SaveManager | 선택 주민·주거·기술·항구 상태가 새 진행 정보 | 별도 추가 확장 티켓. 버전 숫자는 착수 시 실제 파일을 기준으로 결정 |
| CONTENT_CAMPAIGN_DAY1_30 | 특정 인물·날짜의 도입 전제 | 사건 도달 조건과 실제 등장 인물로 배역 조정. 30일 구성 전체를 즉시 재작성하지 않음 |

새 정착안 전체는 기존 선승인 sequence와 같은 작업이 아니다. 첫 작업 지시서는 실행 가능한 별도 범위를 제공하지만, 이번 문서 작성으로 활성화하거나 코드에 적용하지 않는다. 기존 CONTENT-002를 완료로 표시하거나 BETA-010의 재시작 방향 문제를 해결로 바꾸지 않는다.

## 9. 남은 창작 선택

지금 문서를 만들기 위해 답변을 기다릴 필요는 없는 항목이다. 실제 해당 콘텐츠를 제작할 때 고르면 된다.

1. 목재 생산자의 공개 직업명: 현재 구조에 맞춘 ‘나무꾼’ 권장. 목수라는 이름을 유지한다면 2차 목공 역할과의 구분을 설정에 명시.
2. 시작 동행 수: 선택의 차이와 대사·주거 부담을 고려해 2명 권장. 확정 캐논은 아님.
3. 첫 변화의 정서: 함께 먹는 저녁, 텐트 앞 생활 정리, 작은 작업 자리 중 원하는 분위기. 명세는 상품에 맞는 작은 생활 변화로 작성.
4. 관광객 토글: 정착 체험 완성 뒤 포함 권장. 토글이 없어도 첫 체험의 결말이 성립하도록 제작.
5. 본사 안내자의 이름·동물 종과 주민별 개성: 이번에는 직책과 대사 슬롯만 사용하며 새 정식 캐릭터를 임의로 확정하지 않음.

## 10. 검토의 한계

소스·데이터·현재 기록 및 위 공식 자료를 확인했다. 재미·체험 시간·조합별 경제 균형은 아직 플레이테스트로 확인 못 했다. 새 컴파일·Unity Play Mode·저장 재시작·빌드 검증도 이번 문서 작업에서는 수행하지 않았다. 후속 티켓의 검증 절차와 설계 데이터 확인 결과를 각각 분리해서 기록한다.

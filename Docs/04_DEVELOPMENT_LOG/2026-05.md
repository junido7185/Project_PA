## 2026-05-19 - PlayableDay 핫바/인벤토리 표시 및 NPC 모델 자동 배정 보강

### 문제
- 시연 씬에서 플레이어는 보이지만 핫바/인벤토리 슬롯의 아이템이 비어 보였다.
- 스타터 아이템이 실제 플레이어가 아닌 다른 `Inventory/Hotbar`에 들어갈 수 있었다.
- 일부 NPC가 기본 캡슐 또는 모델 미적용 상태로 남아 프로토타입 시연성이 떨어졌다.

### 수정
- `HotbarUI`, `InventoryUI`
  - 런타임에 `Player` 태그 오브젝트의 `Inventory/Hotbar`를 우선 참조하도록 보강.
  - 기존 UI 참조가 비어 있어도 슬롯 UI를 다시 묶고 새로고침하도록 처리.
- `InventorySlotUI`
  - 아이콘이 없는 아이템도 베이지 슬롯과 짧은 텍스트 라벨로 표시되도록 fallback 표시 추가.
  - 슬롯/툴팁/드래그 레이어 null 예외 방어.
- `Inventory`
  - 중복 `Inventory`가 있을 때 `Player` 태그가 붙은 인벤토리를 싱글톤 우선 대상으로 유지.
- `PA_PlayableDayBuilder`
  - 스타터 아이템을 `FindFirstObjectByType` 결과가 아니라 실제 `Player`의 `Hotbar`에 주입.
  - NPC별로 `C-02`~`C-09` 모델을 순차/역할 기반으로 자동 배정.
  - 기존 `NpcModel_` 자식이 중복될 경우 새 모델만 남기도록 정리.

### 검증
```text
dotnet build Assembly-CSharp.csproj --no-restore
결과: 성공, 오류 0개, 경고 CS8785 1개

dotnet build Assembly-CSharp-Editor.csproj --no-restore
결과: 성공, 오류 0개, 경고 CS8785/CS0414
```

### 사용 절차
1. Unity 상단 메뉴 `P.A. System > Project P.A. Hub`
2. `첫날 프로토타입 안전 적용` 실행
3. Play 진입
4. 핫바 1~5번에 빵/당근/목재류가 보이는지 확인
5. 첫 이주자 및 주변 NPC에 캐릭터 모델이 붙었는지 확인

### 🔤 PA_TMPFontFixer — `P.A. System > 🔤 한글·이모지 폰트 자동 설정`

**동작 절차** (한 번 실행으로 영구 적용):
1. `C:\Windows\Fonts\malgun.ttf` (맑은 고딕) → `Assets/Fonts/PA_Korean_Src.ttf` 복사
2. `C:\Windows\Fonts\seguiemj.ttf` (Segoe UI Emoji) → `Assets/Fonts/PA_Emoji_Src.ttf` 복사
3. `TMP_FontAsset.CreateFontAsset()` 으로 Dynamic SDF 자산 생성
   - `samplingPointSize=90`, `atlasWidth/Height=2048`, `AtlasPopulationMode.Dynamic`
   - 한글 11,172자 미리 굽지 않음 → 사용된 글리프만 런타임 atlas 추가
4. `TMP_Settings.defaultFontAsset.fallbackFontAssetTable` 에 등록
   - 모든 TMP 텍스트가 자동으로 fallback 검색 → 코드 수정 불필요
5. `Resources.FindObjectsOfTypeAll<TMP_Text>` 로 모든 TMP 인스턴스 SetAllDirty

**제한사항**:
- Mac/Linux: NotoSansKR-Regular.ttf 를 `Assets/Fonts/PA_Korean_Src.ttf` 로 직접 복사 후 재실행

## 2026-05-07 (계속) — TMP sub-asset 버그 패치 (v2) + NavMesh 자동 Bake

### 사용자 두 번째 덤프 (3건 / 32회)

| 분류 | 건수 | 처리 |
|------|------|------|
| 💥 `Texture2D has been destroyed` (TMP_FontAsset) | ×2 | **PA_TMPFontFixer v1 버그 — v2 패치** |
| 💥 `Material has been destroyed` (TMP_MaterialManager) | ×22 | 동일 원인 |
| ⚠️ `Failed to create agent because there is no valid NavMesh` | ×8 | **NavMesh 자동 Bake 기능 추가** |

### 🐛 핵심 버그 — TMP sub-asset 누락

**원인**: `TMP_FontAsset.CreateFontAsset()` 은 atlas Texture2D 와 Material 을 메모리에 `new`하지만 디스크에 저장하지 않는다. v1 의 PA_TMPFontFixer 는 fontAsset 본체만 `AssetDatabase.CreateAsset` 으로 저장 → 도메인 리로드 시 텍스처·머티리얼 GC 됨 → `MissingReferenceException` 매 프레임 폭주.

**v2 패치**:
- `IsFontAssetHealthy()` — Texture/Material null 검사로 깨진 자산 감지
- 깨진 자산 자동 삭제 후 재생성
- `AddObjectToAsset()` 으로 **atlasTextures 와 material 을 .asset 파일의 sub-asset 으로 영구 저장**
- `RegisterFallbacks()` 에서 깨진/null fallback 엔트리 자동 정리
- `AssetDatabase.SaveAssets()` 즉시 호출로 디스크 기록 강제

### 🧭 NavMesh 자동 Bake (v2)

기존: 안내 다이얼로그만 표시\
v2: `Action_BakeNavMesh()` 가 직접 처리
- Ground 객체에서 `NavMeshSurface` 컴포넌트 탐색 (없으면 추가)
- 리플렉션으로 `BuildNavMesh()` 호출
- 패키지 미설치 시 폴백 안내

Dev Console 의 `🧭 NavMesh Bake 안내` 버튼 → `🧭 NavMesh 자동 Bake` 로 교체.

## 2026-05-08 - NPC 관절 꺾임 안전 모드 보정

### 문제

- 일부 Tripo 계열 NPC 모델(C-02 등)에 공통 Humanoid 걷기/대기 컨트롤러를 강제 연결하면 발목, 무릎, 상체 관절이 비정상적으로 꺾였다.
- NPC 스케일은 플레이어와 맞춰 2배로 키웠지만, 모델별 리그 비율과 휴머노이드 리타겟 결과가 달라 일관된 품질을 보장하기 어려웠다.

### 조치

- `NpcPresentationNormalizer`에 `RootOnlyProcedural` 안전 모드와 `HumanoidProcedural` 맞춤 애니메이션 모드를 추가했다.
  - 기본값은 `HumanoidProcedural`.
  - 유효한 Humanoid Avatar가 있으면 공통 컨트롤러 리타겟 대신 `NpcHumanoidProceduralAnimator`가 Unity muscle 값을 직접 구동한다.
  - Avatar가 유효하지 않은 모델은 자동으로 `RootOnlyProcedural`로 내려가고, NavMesh 이동 + 약한 루트 bob만 적용한다.
- `NpcController`, `PA_RuntimeSceneBinder`, `PA_DevConsole`, `PA_SceneAutoBuilder`가 모두 NPC를 맞춤 절차 애니메이션 모드로 보정하도록 통합했다.
- 런타임 바인더에서 NPC별 컴포넌트를 씬 전체 싱글턴 방식으로 찾던 부분을 수정해, 각 NPC에 `NpcPresentationNormalizer`가 개별 적용되도록 했다.

## 2026-05-12 - 빌딩 스케일 정규화 기준 추가

### 문제

- 플레이어/NPC가 2배 스케일 기준으로 커져 있는데, Tripo3D에서 가져온 빌딩 FBX는 원본 bounds가 제각각이라 캐릭터와 월드 크기가 맞지 않았다.
- 프리팹 scale을 수동으로 만지면 나중에 모델을 교체할 때 다시 틀어질 수 있었다.

### 조치

- `PA_ContentAutoIntegrator`에 캐릭터 기준 높이 `3.6m`를 명시하고 B01~B12의 목표 월드 크기를 재정의했다.
- 모델 생성 시 Renderer bounds를 읽어 목표 크기에 맞게 uniform scale로 자동 보정한다.
- 보정 후 모델 중심을 XZ 원점에 맞추고 바닥을 Y=0에 붙여, Collider/NavMeshObstacle/상호작용 위치가 일관되도록 했다.
- 검증 단계에서 프리팹의 대표 `BoxCollider.size`가 목표 크기와 다르면 경고하도록 보강했다.

### 대표 목표 크기

```text
B01 노점 상점: 5.0 x 4.2 x 4.0
B02 잡화점: 8.0 x 6.0 x 6.0
B03 편의점: 10.0 x 6.2 x 7.0
B04 백화점: 13.0 x 10.0 x 8.5
B05~B08 작업대: 캐릭터 허리/가슴 높이에 맞춘 2~3m급
B09 창고: 7.0 x 5.2 x 5.5
B10 NPC 집: 8.0 x 6.2 x 6.5
B11 광장 시설: 6.0 x 1.8 x 6.0
B12 무역 항구: 10.0 x 1.3 x 5.0
```

```text
$ dotnet build Assembly-CSharp-Editor.csproj --no-restore
결과: 성공, 오류 0

```

## 2026-05-11 - SaveData v4 지속성 및 초기 경제 데이터 밸런싱

### 변경 이유

- `SaveData` v3는 친밀도 점수와 고용 후보 목록만 복구해, 대화 1일 1회 친밀도 제한과 고용 NPC의 실제 위치/FSM 상태가 저장되지 않았다.
- 고용 NPC 로드가 `TryHire`를 다시 호출해 비용 차감/티어 검사 경로를 탈 수 있었고, 저장된 씬 상태 복구와 맞지 않았다.
- `PA_DataCreator`가 기존 에셋을 스킵해서 아이템/레시피 밸런스를 한 번에 최신화하기 어려웠다.

### 조치

- `SaveData` 스키마를 v4로 올리고 `FriendshipRecord.lastDialogueDay`, `HiredNpcRecord`의 `hiredNpcId`, 위치/회전, active FSM, 소비/생산/전문가 FSM 상태를 추가했다.
- `SaveManager` 마이그레이션을 v0→v4 체인으로 확장하고, v3 세이브는 고용 NPC transform 미보유 상태로 안전하게 기본 스폰 복구되도록 처리했다.
- `FriendshipService`에 마지막 대화 보상 일자 저장/복구 API를 추가했다.
- `HiringService`에 런타임 고용 NPC 스냅샷과 비용 차감 없는 복구 API를 추가했다.
- `NpcController`, `ProducerNpcController`, `SpecialistNpcController`에 `GetFsmState`/`RestoreFsmState`를 추가하고, Instantiate 직후 `Start()`가 복구 상태를 Idle로 덮지 않도록 복구 플래그를 넣었다.
- `PA_DataCreator`를 15개 아이템/8개 레시피 업서트 도구로 개편했다. 기존 SO도 같은 기준으로 갱신되며, 현재 `Resources/Items`, `Resources/Recipes` 에셋에도 밸런스 값을 반영했다.

### 밸런스 기준

- 초반 원재료는 낮은 단가와 빠른 회전율 유지: Wheat 10, Carrot 12, Wood 8, Ore 15, Fish 18.
- 1차 가공품은 10~40% 마진: BreadLoaf 34, IronBar 42, Plank 24.

- 중반 해금 상품은 Tier 요구와 고마진 역할 분리: 철제 도구 Tier 1, 목제 가구/의류 Tier 2.

   빌드 전 Build Settings 에서 수동 제거 권장.

## 2026-05-19 - 첫날 프로토타입 시연성/상호작용 안정화

### 문제

- 시나리오 단계는 있으나 실제 씬에서 어떤 NPC, 어떤 판매대, 어떤 슬롯과 상호작용해야 하는지 구분이 어려웠다.
- 모델링/아이콘이 완성되지 않은 상태라 상품 진열 성공 여부가 눈에 보이지 않았다.
- `PlayerInteraction`이 정면 `SphereCast`에만 의존해 낮은 판매대 슬롯을 놓치기 쉬웠다.
- `ShopSlot`은 현재 선택된 핫바 슬롯이 비어 있거나 잘못 선택되어 있으면 진열이 실패해, 프로토타입 시연이 자주 막혔다.

### 수정

- `PlayerInteraction` 보강
  - 정면 `SphereCast` 실패 시 주변 반경에서 가장 적절한 `IInteractable`을 한 번 더 탐색.
  - 판매대처럼 낮거나 작은 오브젝트도 가까이 있으면 `[Space]` 프롬프트와 상호작용이 잡히도록 수정.
- `ShopSlot` 보강
  - 선택한 핫바 슬롯에 판매 가능 아이템이 있으면 기존처럼 해당 아이템 진열.
  - 선택 슬롯이 비어 있거나 판매 불가이면 핫바/인벤토리에서 첫 판매 가능 아이템을 자동 선택해 진열.
  - 진열 성공 시 판매대 위에 임시 모델/큐브와 `아이템명 + 가격` 월드 라벨 표시.
  - 회수, NPC 구매, 저장 복구 시 진열 표시를 갱신.
- `PrototypeWorldLabel` 추가
  - 프로토타입 전용 월드 라벨 컴포넌트.
  - 카메라를 바라보는 3D 텍스트로 첫 이주자, 판매대 슬롯, 보급품, 스마트폰 안내를 표시.
- `PA_PlayableDayBuilder` 보강
  - 유효한 ShopSlot이 부족하면 `[FirstDayPrototype]/Prototype_Shop_For_Demo` 아래 시연용 판매대와 슬롯 4개를 비파괴 생성.
  - 판매대 슬롯 Collider를 크게 보정.
  - 첫 이주자/판매대/보급품/스마트폰 안내 라벨 자동 생성.
- `PlayableDayScenarioController` 안내 문구 보강
  - "노란 판매대 슬롯", "머리 위 첫 이주자 표식"처럼 실제 화면에서 찾을 수 있는 기준으로 목표 문구 변경.

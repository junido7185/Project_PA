### 싱글톤 서비스 배치 순서 (DefaultExecutionOrder 기준)

빈 `GameObject`를 만들고 아래 순서대로 컴포넌트를 붙인다. 이름은 `[Services]`처럼 그룹화하면 씬 정리에 유리하다.

```
1. EconomyService        (Order -100)  → startingMoney 설정
2. TierService           (Order -90)   → tierDefinitions 리스트에 SO 5개 등록
3. GameClock             (Order -80)   → startHour, daysPerSeason 설정
4. ItemRegistry          (Order -70)   → allItems 에 모든 Item SO 등록
5. HiringService         (Order -60)   → availableCandidates, spawnPoint 설정
6. FriendshipService     (Order -60)   → hiddenBlueprints 등록
7. GridService           (Order -50)   → cellSize = 2.0 (BuildManager.gridSize 와 일치)
8. AuditService          (Order -40)   → auditIntervalDays, 조건값 설정
9. BuildingRegistry      (기본값)       → 필드 없음, 빈 GameObject에 추가만
```

### 스크립트별 Inspector 필수 연결 필드

**[Player 오브젝트]**
- `PlayerController` — 이동 입력 자동 (PlayerInputHandler 구독)
- `PlayerInteraction` — interactionRange, interactLayer
- `Inventory` — `slots` 리스트 (InventorySlot 참조), `hotbar` 참조
- `Hotbar` — slots 리스트

**[BuildManager 오브젝트]** (플레이어 자식 또는 별도)
- `gridSize = 2.0`, `buildDistance`, `obstacleLayer`

**[SaveManager 오브젝트]**
- `allBuildingTypes` — 씬에서 지을 수 있는 모든 `BuildingData` SO 등록

**[Shop 오브젝트]** (Tag = `"Shop"`)
- `managedSlots` — 씬에 배치한 `ShopSlot` 컴포넌트들 등록
- TierDefinition에 `shopSlotCount` 설정 후 `ApplyTierSlots()` 자동 호출

**[Workbench 오브젝트]** (각 작업대별)
- `workbenchType` — Kitchen / Forge / SewingTable / BasicWorkbench 중 선택
- Collider 필수 (PlayerInteraction 레이캐스트 히트용)

**[소비형 NPC]**
- `NpcController` — profile, wanderRadius, shopTag
- `NpcDialogue` — dialogueData, friendshipId (NPC별 고유 문자열)
- `NpcScheduleController` — profile, scheduleData, consumerController, homePoint

**[생산형 NPC]**
- `ProducerNpcController` — profile, productionData, specialty, workSpot, dropOffPoint
- `NpcScheduleController` — producerController 연결

**[전문가 NPC]**
- `SpecialistNpcController` — profile, specialty, targetWorkbench, assignedRecipes
- `NpcScheduleController` — specialistController 연결

**[NavMesh]**
- 씬 전체 지형에 NavMesh Bake 필수
- NPC 오브젝트에 `NavMeshAgent` 컴포넌트 추가

---

### 씬 구성 권장 순서

```
① 지형 배치 (Terrain or Mesh) → NavMesh Bake
② 서비스 GameObjects 배치 (위 순서대로)
③ 플레이어 오브젝트 배치 + Inventory 구성
④ Shop + ShopSlot 배치 및 연결
⑤ Workbench 오브젝트 배치
⑥ 건물 프리팹 배치 (BuildingData SO 생성 후 SaveManager 등록)
⑦ NPC 프리팹 배치 + NpcProfile, NpcDailySchedule SO 연결
⑧ 채집 포인트 / Farmland 배치
⑨ UI Canvas 배치 (인벤토리 UI, HotbarUI 등)
⑩ 전체 플레이 테스트
```

## 2. 디자인 컨셉 — Cozy Low-Poly Island Town

### 핵심 키워드
```
아늑함(Cozy) · 로우폴리(Low-Poly) · 파스텔 · 섬마을 · 따뜻함 · 단순한 형태
```

### 색상 팔레트

| 용도 | 색상명 | HEX 근사값 |
|---|---|---|
| 잔디/자연 기본 | 밝은 올리브 그린 | `#8DB87A` |
| 흙/모래 | 따뜻한 베이지 | `#D4B896` |
| 나무 건물 | 따뜻한 오크 브라운 | `#A07850` |
| 지붕/강조 | 테라코타 오렌지 | `#D4714A` |
| 하늘 | 연한 스카이 블루 | `#B0D8E8` |
| 바다/강 | 청록색 | `#5BAFC0` |
| 플레이어/UI 강조 | 산호 핑크 | `#F08070` |
| 선택/하이라이트 | 따뜻한 옐로우 | `#F5D76E` |

**계절별 팔레트 보정:**
- Spring: 채도 +15%, 밝기 +10% (생동감)
- Summer: 채도 +20%, 하이라이트 강조
- Autumn: 오렌지·노랑 계열로 shift
- Winter: 채도 -40%, 청백색 계열 (눈 효과)

### 형태 언어
- **둥근 모서리:** 날카로운 각 없음. 건물 모퉁이, 아이템 모두 부드럽게
- **단순한 폴리곤:** 실루엣으로 오브젝트를 인식 가능한 수준
- **약간 과장된 비율:** 캐릭터는 머리가 몸의 1/4~1/3 (미니 치비 방향)
- **밝고 균일한 조명:** 강한 그림자 없음. Ambient 위주

### 참고 레퍼런스

| 레퍼런스 | 참고 요소 |
|---|---|
| Animal Crossing: New Horizons | 섬 마을 레이아웃, NPC 감성, 건물 진화 흐름 |
| Stardew Valley | 색상 팔레트, 아이템 아이콘 밀도 |
| Synty Studios POLYGON Town Pack | 로우폴리 건물·환경 스타일 (Unity Asset) |
| Quaternius Free Pack | 무료 로우폴리 캐릭터 비율 참고 |
| Dinkum | 호주풍 island town 레이아웃 |

### 마을 레이아웃 방향

```
[해변/무역항 (남쪽)]
       ↕
[상점 거리 (중앙)]  ←→  [광장/NPC 사교 공간]
       ↕
[주거 구역 (서쪽)]  [공방 구역 (동쪽)]
       ↕
[채집/파밍 구역 (북쪽)]
```

- 그리드 셀 2.0 unit = 약 2m 기준
- 상점 중심 → 방사형으로 확장되는 구조
- Tier 업 시 건물이 외곽으로 확장됨 (중심은 상점 유지)

## 4. Tripo3D.ai 모델링 발주 가이드 (상세)

> **목표**: 1인 졸업작품으로 캐릭터 9 + 건물 12 + 환경 8 + 소품 6 = **약 35개 3D 에셋**을
> 일관된 스타일로 빠르게 확보. 모든 에셋이 **단일 아트 톤(cozy island low-poly)** 을 유지하고
> Unity URP + Mixamo 오토리깅 파이프라인에 그대로 끼워 들어가야 한다.
> **타겟 도구**: Tripo3D.ai (https://www.tripo3d.ai) — 텍스트→3D / 이미지→3D AI 서비스.

### 4.1 발주 워크플로우 (전체 흐름)

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌──────────────┐    ┌──────────────┐
│ 1. 사이트    │ →  │ 2. 프롬프트  │ →  │ 3. 미리보기  │ →  │ 4. FBX 다운  │ →  │ 5. Unity 임포트│
│   가입/로그인 │    │   입력+설정   │    │   품질 판정   │    │   + 텍스처   │    │   + Mixamo    │
└─────────────┘    └─────────────┘    └─────────────┘    └──────────────┘    └──────────────┘
```

**한 번 발주에 평균 90초 소요** (생성 60초 + 검수 30초). 캐릭터 9종 발주는 약 15분.

### 4.2 Tripo3D 사이트 설정 패널 가이드 (실제 UI 기준)

Tripo3D 는 발주 시 두 가지 **생성 모드** 중 하나를 고른다. 각 모드의 옵션 셋이 다르므로
**무엇을 발주하느냐에 따라 모드를 다르게 선택**해야 한다.

#### 🎯 어느 모드를 쓸 것인가 — 결정 트리

```
캐릭터 (Mixamo 리깅 필요)?
   └─ YES → ✅ HD 모델 (Quad 토폴로지 + 부분별 생성 ON 필수)

건물·환경 타일·핵심 소품 (게임에서 가까이 보임)?
   └─ YES → ✅ HD 모델 (텍스처 품질·토폴로지 컨트롤 필요)

작은 장식 소품·테스트 / 크레딧 절약?
   └─ YES → 🟡 스마트 메시 (빠르고 저렴, 단 삼각형만)

이미 발주된 결과를 더 다듬고 싶다?
   └─ YES → HD 모델 의 Re-Refine 사용
```

> 💡 **이 프로젝트의 권장**: 캐릭터·건물·핵심 소품은 모두 **HD 모델**, 잔디 타일·울타리 같은
> 단순 환경 자산은 **스마트 메시** 로 분리해 크레딧 절약.

---

#### 🟢 HD 모델 (HD Mode) — 캐릭터·건물·핵심 소품용

| 옵션 | 권장 값 | 이유 |
|------|---------|------|
| **입력 모드 (텍스트를 모델로 등등)** | 일관성 강제 시 `이미지를 모델로` (캐릭터 basecolor PNG 첨부) / 그 외 `텍스트를 모델로` | §6.1.C 참고 |
| **텍스처** | **ON** | 캐릭터 옷·건물 외관 색상 필수 |
| **고해상도 텍스처** | 캐릭터·핵심 건물 = ON / 일반 환경 = OFF | ON 시 atlas 가 2K 이상 — 가까이 봐도 깔끔 |
| **PBR** | **OFF** | 프로젝트는 URP Lit Flat 단색 셰이더 위주, PBR 켜면 metalness/roughness 맵까지 생성되어 용량만 늘어남 |
| **토폴로지** | **쿼드 (Quad)** ✅ | Mixamo Auto-Rig 가 사각면 토폴로지를 선호. 삼각형으로 가면 리깅 정확도 떨어짐 |
| **폴리곤 수** | 캐릭터 = `Standard 3K~5K` / 건물 = `Standard 1K~3K` / 소품 = `Low ≤1K` | 모바일/저사양 PC 친화 |
| **울트라 메시 품질** | 캐릭터 = ON / 건물·소품 = OFF | ON 시 원본 메쉬가 더 정밀해지지만 크레딧 추가 소비 |
| **부분별 생성** | 캐릭터 = **ON** ✅ / 건물·소품 = OFF | ON 시 body / head / hands / feet / hat 등이 **분리된 메쉬 그룹** 으로 출력 → Mixamo 리깅 + Unity 머티리얼 분리에 핵심 |
| **개인정보 보호** | `Public` (Free) 또는 `Private` (Pro 만 가능) | 졸업작품이면 Private 권장 |
| **AI 모델** | 최신 버전 (예: `Tripo v2.5`) | 신모델일수록 토폴로지·텍스처 품질 ↑ |

> 🔑 **부분별 생성 ON 의 위력**: 이 옵션이 켜져 있어야 모자, 앞치마, 도구 가 **별도 메쉬**로
> 나와 Unity 에서 머티리얼을 따로 입힐 수 있다. 끄면 캐릭터 전체가 1 mesh + 1 atlas 로 합쳐져
> "옷 색만 바꾸기" 같은 변형이 어렵다. **캐릭터 발주 시 절대 끄지 말 것**.

> 💎 **울트라 메시 품질 vs Re-Refine**: 첫 발주에서 ON 켜면 처음부터 고품질로 만든다.
> OFF 로 발주 후 결과가 미흡하면 `Re-Refine` 으로 1회만 추가 다듬을 수 있다 (크레딧 +1).
> **권장**: 캐릭터는 첫 시도부터 ON, 그 외는 OFF 로 빠르게 보고 필요시 Re-Refine.

#### 🟡 스마트 메시 (Smart Mesh) — 단순 소품·환경·테스트용

|------|---------|------|

### 4.3 공통 프롬프트 구조 (3-블록, Positive-Only)

> ⚠️ **2026-05-11 중요 정정**
> 이전 가이드는 4-블록 (A/B/C/D) 구조였고 [D] NEGATIVE 를 "별도 입력란" 에 넣으라고
> 적혀 있었지만, **Tripo3D 사이트에는 Negative 전용 입력란이 존재하지 않는다** (텍스트
> 입력창 하나뿐). 결과적으로 [D] 가 메인 프롬프트에 합쳐져 들어가면 AI 가 `broken topology`,
> `n-gons`, `multiple separate objects`, `floating parts` 같은 **부정 키워드를 생성 의도로**
> 해석한다. 실제 발주 결과물(B-10 건물 측면 구멍, B-06 조리대 옆구리 관통)이 정확히 이
> 패턴이었음을 확인했다.
>
> **모든 발주는 아래 positive-only 3-블록만 사용한다.** 단순 "no X" 형태의 명시적 부정은
> AI 가 directive 로 해석하므로 안전 — 다만 결함을 묘사하는 형용사 (broken, defective,
> low quality) 는 절대 사용하지 않는다.

모든 발주는 **동일한 3개 블록을 같은 순서**로 결합한다.

```
[A] STYLE_PREFIX     (스타일 + 메시 품질 + 공통 금지사항 — 모두 긍정형/no-directive)
[B] CORE_DESCRIPTION (대상 자체 묘사 — 매 항목 다름)
[C] TECHNICAL_SUFFIX (카테고리별 형상/스케일/원점 제약)
```

#### [A] STYLE_PREFIX (모든 에셋 공통, 그대로 복사)
```
low poly 3D game asset, cozy island town style, soft warm pastel colors,
rounded shapes, stylized cartoon, Unity URP game-ready,
clean watertight manifold mesh, all quad faces, single connected solid object,
flat shading, single matte diffuse color only, ambient occlusion baked off,
no PBR, no metallic, no glossy surface, no specular highlights,
no subsurface scattering, no photorealism, no realistic skin pores,
no text, no letters, no signs, no watermark, no logo, no signature,
no base plinth, no shadow disc, no ground patch under the object
```

> 🔑 **변경 핵심**: 이전 [D] NEGATIVE 의 결함-묘사 키워드 (`broken topology`, `n-gons`,
> `floating parts`, `multiple separate objects`) 는 **모두 긍정형 mesh-quality 키워드로 치환**
> 했다 → `clean watertight manifold mesh, all quad faces, single connected solid object`.
> 결함 단어 자체가 프롬프트에서 사라졌으므로 AI 가 결함을 "생성 의도" 로 해석할 여지가 없다.

#### [C] TECHNICAL_SUFFIX — 카테고리별

```
[C-Character] humanoid character, T-pose with arms straight horizontally,
              symmetrical body, rigging-ready for Mixamo auto-rig,
              slightly chibi proportions (head ~1/4 of body height),
              friendly neutral face expression, mouth closed,
              separate mesh groups for body / head / hands / feet,
              no held props in hands, hands open palms down,
              no detailed human anatomy, no fingernails, no facial wrinkles,
              no weapons, no gore,
              standing on ground at Y=0, centered on origin

[C-Building] 3D building exterior model, exterior shell only without interior,
             watertight outer hull with attached roof and walls,
             bottom flat at Y=0, centered on X/Z origin,
             real-world scale in meters as specified,
             no surrounding terrain, no scattered foliage, no characters,
             no plant decorations growing from the walls

[C-Prop]     standalone prop, single solid object, bottom flat at Y=0,
             centered on origin, real-world scale in meters,
             no environment around the prop

[C-Terrain]  flat terrain tile, single quad-based plane mesh,
             bottom flat, top displays surface details only,
             tileable on X/Z so adjacent copies seam perfectly,
             no props placed on the tile
```

> 🧱 **건물 발주 시 추가 주의 (B-06 조리대 사고 방지)**
> 화덕·찬장·창고처럼 **내부 공간이 있는 오목 구조** 를 발주할 때는 [B] CORE_DESCRIPTION 에
> `exterior shell with the front opening sealed as a flat decorative surface (no real cavity)`
> 한 줄을 추가한다. Tripo3D 는 concave 내부 공간을 그릴 때 face normal 이 뒤집혀 측면
> 관통 구멍이 나는 게 가장 흔한 실패 패턴 — 처음부터 cavity 자체를 만들지 말도록 강제한다.

> 🔧 **A-Pose 폴백**: T-Pose 가 안 나올 때만 `A-pose acceptable as fallback` 을 [C-Character] 에
> 추가. 그 외에는 절대 폴백 허용하지 말 것 — Mixamo Auto-Rig 가 실패한다.

## 7. Mixamo 오토리깅 파이프라인

### Step 1 — Tripo3D.ai에서 내보내기

1. Tripo3D에서 모델 생성 완료 후 **Download** 클릭
2. 형식: **FBX** 선택 (`.fbx`)
3. Pose 옵션: **T-Pose** 강제 선택 (없으면 A-Pose도 허용되나 T-Pose 권장)
4. 텍스처: 포함해서 내보내기 (나중에 단색으로 교체 가능)

### Step 2 — Mixamo 업로드 및 오토리깅

1. [mixamo.com](https://www.mixamo.com) 접속 → Upload Character
2. FBX 파일 업로드
3. **Auto-Rig 마커 배치:**
   - Chin (턱): 머리와 목 경계
   - Wrists (손목): 손목 관절 중심
   - Elbows (팔꿈치): 팔꿈치 바깥쪽
   - Knees (무릎): 무릎 앞쪽
   - Groin (사타구니): 다리가 갈라지는 지점
4. **Skeleton LOD:** 65 bones (기본값 유지)
5. 리깅 완료 후 **T-Pose** 확인 → Proceed

### Step 3 — 애니메이션 다운로드

기본 필요 애니메이션 목록:

| 애니메이션 | Mixamo 검색어 | 용도 |
|---|---|---|
| 기본 대기 | `Idle` | 모든 NPC/플레이어 기본 상태 |
| 걷기 | `Walking` | NavMeshAgent 이동 |
| 뛰기 | `Running` | 플레이어 대시 (선택) |
| 작업 | `Digging` / `Chopping` | 생산형 NPC Working 상태 |
| 가공 | `Sword And Shield Idle` (반복) | 전문가 NPC CraftingAtBench 상태 |
| 대화 | `Talking` | NpcDialogue 상호작용 |
| 쇼핑 | `Looking Around` | NpcController 쇼핑 상태 |

다운로드 설정:
- Format: **FBX for Unity (.fbx)**
- Skin: **With Skin** (첫 번째 애니만, 이후는 Without Skin으로 용량 절약)
- Frames per Second: **30**
- Keyframe Reduction: **none** (나중에 Unity에서 최적화)

### Step 4 — Unity Import 설정

1. FBX를 `Assets/Models/Characters/[직종명]/` 폴더에 복사
2. Inspector > Rig 탭:
   - Animation Type: **Humanoid**
   - Avatar Definition: **Create From This Model** (첫 번째 캐릭터)
   - 이후 캐릭터: **Copy From Other Avatar** → 공유 가능
3. Inspector > Animation 탭:
   - 각 애니메이션 클립 Loop 설정 (Idle/Walk/Run/Work → Loop Time 체크)
4. Animator Controller 생성:
   - `Assets/Animations/NpcAnimatorController.asset`
   - 모든 Humanoid 캐릭터가 동일한 컨트롤러 공유 가능 (Avatar 공유 덕분)

### 텍스처 전략

**옵션 A — Vertex Color (권장 · 가장 단순)**
- 텍스처 파일 없음
- Tripo3D 생성 후 Unity에서 단색 Material 교체
- URP/Lit 셰이더 또는 URP/Simple Lit 사용
- 팔레트 표의 HEX 값으로 Material Color 직접 지정

**옵션 B — 단색 팔레트 텍스처 (Atlas)**
- 512×512 픽셀 한 장에 모든 색상 배치
- 모든 모델이 UV를 이 텍스처의 특정 색상 픽셀로 지정

## 10. 건물 진입 시스템 — 씬 세팅 (단일 씬 오프셋 방식)

> **선택 근거:** 씬 분리(Additive/LoadScene) 대비 NavMesh·싱글톤 서비스·SaveManager
> 상태가 그대로 유지되어 1인 16주 MVP 에 가장 저비용이다. 실내는 외부 월드와
> **Y=+100 오프셋**에 배치해 카메라 컬링만으로 시각 분리.

### 관련 스크립트 (세션 15 추가)

| 스크립트 | 역할 |
|---|---|
| `BuildingEntrance.cs` | 문 오브젝트에 붙이는 IInteractable. F키로 `targetSpawn` 워프 |
| `UI/ScreenFader.cs` | 검은 화면 페이드. `Instance.PlayWarpFade(onMidpoint)` 호출 |
| `CameraController.SnapToTarget()` | 워프 직후 카메라 Lerp 스킵 (실내↔실외 긴 패닝 방지) |

### 배치 절차

```
① [Services] 그룹에 빈 GameObject "ScreenFader" 추가 → ScreenFader 컴포넌트 부착
   (Canvas·Image·CanvasGroup 은 Awake 에서 자동 생성됨)

② 각 건물 외부 문 앞에 빈 GameObject "Door_Out_{건물명}" 생성
   - Collider 추가 (Box 추천, IsTrigger = 끔)
   - Layer = Interact (PlayerInteraction.interactLayer 와 동일)
   - BuildingEntrance 컴포넌트 부착
     · targetSpawn = 실내 스폰 지점 Transform
     · promptLabel = "상점 입장" 등

③ 실내 영역 루트를 외부 월드에서 Y=+100 위치에 배치
   "Interior_{건물명}" 빈 GameObject 안에:
   - 실내 벽·바닥·천장 메쉬
   - "PlayerSpawn_Inside" 빈 GameObject (= targetSpawn 대상)
   - "Door_In_{건물명}" 빈 GameObject + BuildingEntrance
     · targetSpawn = 외부 "PlayerSpawn_Outside"
     · promptLabel = "나가기"

④ 외부에도 "PlayerSpawn_Outside" 배치 (내부 문의 워프 복귀점)
```

### NavMesh 주의

- 실내 층에도 NavMesh 가 필요하다면 **Y=+100 영역까지 포함해 Bake**.
- 플레이어만 들어가고 NPC 는 안 들어간다면 실내는 Bake 생략 가능.

### 저장/로드 호환성

- `SaveManager` 는 플레이어 `transform.position` 만 저장 → Y=+100 위치라도 문제 없이 복원.
- 재진입 시에도 실내 상태가 유지됨 (씬 내 GameObject 이므로).

### 확장 포인트

- **맵 간 빠른 이동:** `BuildingEntrance` 에 `requiredTier` 필드 추가 → `TierService` 로 제한.
- **야간 상점 잠금:** `GameClock.CurrentHour` 를 Interact 진입부에서 체크.
- **NPC 출입:** `NpcScheduleController` 가 근처 Door_In 트리거를 목표로 하면 자동 출퇴근 가능.

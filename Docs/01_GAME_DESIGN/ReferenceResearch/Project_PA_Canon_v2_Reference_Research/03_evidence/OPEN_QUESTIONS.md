## 캡처 프로토콜 제안(H)

각 클립은 하나의 질문만 해결한다. 게임·플랫폼·빌드·해상도·입력 방식·시간 배율·fixture 여부를 먼저 기록한다. 입력 오버레이와 가시 상태가 함께 보이면 가장 좋다. 편집본이면 컷을 표시하고 컷을 넘는 동작 지속시간은 측정하지 않는다. 사운드가 있는 경우 음악/환경/행동 신호를 구분해 듣되 원작 음원은 복제하지 않는다.

P.A.는 같은 자연 입력 경로에서 ‘성공→실패→회복’을 촬영한다. 정상 행동만 찍으면 가장 흔한 문제인 입력 유실·잔류 잠금·중복 획득·잘못된 성공음이 숨는다. 영역/가격 같은 값은 동작 전후 로그로 확인하고, 플레이어가 읽는 화면과 로그의 의미가 같아야 한다.

## 새 근거를 반영하는 방법

새 사실은 SOURCE_LEDGER에 새 ID로 추가하고 기존 V/D를 덮어쓰지 않는다. 바뀐 버전이면 기존 관찰을 폐기하기보다 버전 범위를 좁힌다. 영향받는 H·작업 단위·품질 시나리오를 함께 고친다. 결과를 본 뒤 지연이나 임계값을 정해야 할 필요가 생겼다면 ‘P.A. 제안값’으로 기록하고 원작 측정값과 분리한다.

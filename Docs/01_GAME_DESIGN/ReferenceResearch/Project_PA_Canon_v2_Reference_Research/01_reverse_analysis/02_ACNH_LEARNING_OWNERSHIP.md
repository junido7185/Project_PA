# Animal Crossing: New Horizons: 배우는 문법과 공간 소유

연구 대상: 튜토리얼 전이, 재료와 도구의 의미, 정착/꾸미기의 판단. Canon §1.1·§3–5·§7–12·§22. 근거 AC-D1–3. **이번 연구의 ACNH 근거는 문헌 중심(D)이며 플레이 영상 프레임 분석(V)이 아니다.**

## 문헌이 확인하는 최소 규칙

Nintendo 시작 팁은 손에 맞는 도구를 들고 자원을 얻는 방식, 조리법에서 필요한 재료를 보는 방식, Phone의 정보 접근과 제한된 가방을 설명한다. 곤충은 facing swing 또는 조심스러운 접근, 낚시는 그림자 앞에 캐스팅한 뒤 입질에 대응한다고 안내한다(D, AC-D1). GameWith 입문 가이드는 입지를 이동 목적과 연결하고 낚시 입질을 시각·소리로 구분한다(D, AC-D2). 자유로운 안팎 꾸미기는 AC-D3에 설명되어 있다.

원작의 구체적인 성공 윈도, 배치 유효성 검사, pocket 추가 순서, 카메라 모션은 U다. 이 문서는 위 규칙이 만들어내는 학습 조건을 역으로 설명한다(I).

## ‘무엇을 할 수 있나’에서 ‘무엇을 만들고 싶나’로

재료 수집을 먼저 긴 과제 목록으로 설명하면 플레이어는 목표 카운터를 채운다. 반면 손에 든 도구·눈앞의 자연물·구체적인 제작물을 연결하면 같은 행동에 공간적 목적이 생긴다(I). 중요한 것은 조리법 UI에 재료 이름이 있다는 사실보다, **부족한 재료를 어디서 어떤 행동으로 얻는지 연결할 수 있는가**다.

P.A. 본사에서는 이 전체 제작 체계를 미리 가르치면 안 된다(C). 대신 사과 하나의 연속성으로 문법을 완성한다.

| P.A. 행동 C | 플레이어가 읽어야 할 사실 H | 실패를 감추는 나쁜 구현 |
|---|---|---|
| 빈손 E 나무 흔들기 | 나무가 반응하고 사과가 떨어짐 | 흔들기 직후 보이지 않게 가방에 사과 지급 |
| 바닥 사과 E 줍기 | 바닥 물건이 실제 가방/핫바로 옮겨짐 | 드롭과 가방 보상을 둘 다 지급 |
| 숫자 키 선택 | 선택 칸과 손의 물건이 같은 사과 | HUD 선택만 바뀌고 held 표현 늦음 |
| X | 손은 비지만 물건은 가방에 남음 | 선택 슬롯 지우기/다른 항목으로 바꾸기 |
| 사과 들고 가판대 E | 내 상품의 위치·수량이 바뀜 | 가방 전체를 훑어 임의 상품 진열 |
| 가격 Drag → 고객 반응 | 내가 바꾼 조건에 누군가 반응 | 가격창만 바뀌고 실제 거래는 예전 가격 |

이 연속성 덕분에 섬에서 새로운 도끼를 받을 때는 ‘손에 들고 대상 앞에서 E’라는 기존 이해 위에 **어떤 도구가 어떤 대상에 맞는가**만 추가하면 된다(I). 낚시·배치·Workbench·전문 분야까지 본사에서 암기시키는 것은 Canon 위반이면서 이 전이의 장점을 잃는다.

## 정보는 행동의 의문을 해결할 때 가치가 있다

Phone와 조리법은 행동을 위한 참조라는 구조를 갖는다(D). P.A.로 전환할 때 Phone는 가방 속 지급 아이템이 아니라 P 시스템 UI다(C). 첫 도끼 앞의 힌트, Workbench 앞의 tap/hold 안내, OPEN 전 최소 재고 안내는 현재 의문에 답하면 된다(H).

정보의 두 수명을 분리한다(H). 순간 힌트는 지금 눈앞의 행동을 알려주고, 기록은 놓친 사실을 다시 찾게 한다. 놓친 알림이 기록되어도 P에서 해당 화면으로 들어갈 수 없으면 정보 접근은 완성되지 않았다. 현재 저장소의 DispatchLog/Feed 진입 불가 기록은 이 원리를 실제 검수 대상으로 만든다(R).

같은 메시지를 대화·토스트·하단 프롬프트가 동시에 표시하면 안내의 양은 많아도 어떤 입력을 받아야 하는지 모호하다. 표시 우선순위와 입력 소유자를 함께 정해야 한다. 가격창이 열려 있는데 뒤의 E 힌트가 남으면 플레이어는 세계와 UI 어느 쪽이 E를 받는지 예상할 수 없다.

## 공간 소유는 입지의 결과를 예측할 수 있을 때 성립한다

입지는 생활 동선과 연결된다는 문헌 설명(D, AC-D2)을 P.A.의 ‘문과 접근 여백을 보며 배치한다’는 원리로 전환한다(I). 건물 종류를 늘리는 것보다 후보 위치의 다음 결과가 읽히는 것이 중요하다.

미리보기는 세 가지 질문에 답해야 한다(H). 실제 놓일 모델은 얼마나 큰가. 입구가 어디를 향하는가. 왜 여기서는 놓을 수 없는가. 색 하나로 invalid를 알리는 것은 첫 질문과 둘째 질문을 해결하지 못한다. footprint만 맞추고 문을 수목/벽에 붙이면 플레이어는 유효 표시를 믿고 진행을 막는 선택을 하게 된다.

P.A. 텐트는 직업 집이 아니라 일반 Resident Tent이며 선택한 무주택 동행에게 자동 배정한다(C). 주택의 종류를 직업에 매칭시키는 퍼즐을 만들면 공간 소유와 동행 선택 대신 정답 맞추기 경험이 생긴다. 텐트의 입구·동행의 생활 위치가 읽히면 배정 규칙을 설명하는 긴 UI 없이도 선택한 두 인물이 정착했다는 결과를 보여줄 수 있다(H).

## 원작에서 옮기지 않을 세 가지

현실 시간은 P.A. Soft Clock의 근거가 아니다. Miles 프로그램을 데모의 지속 과제 목록으로 복제하지 않는다. 원작의 과일 힘에 따른 채집/파괴 변화를 P.A. 도구 실패 규칙에 섞지 않는다. 이것들은 각 게임의 구조 안에서는 의미가 있지만 P.A. Canon에는 다른 시간·안내·내구도 계약이 있다.

## 반증 가능한 적용 판단

처음 플레이한 사람이 본사 사과 이후 새 물건의 손/가방/진열 관계를 설명할 수 있으면 문법이 전이됐다. 힌트를 닫고도 행동할 수 있으면 학습 자료가 기능했다. 유효 배치 후 입구를 찾고 왕복할 수 있으면 미리보기가 결과를 예측했다. 이 세 가지가 실패하면 더 많은 텍스트부터 추가하지 말고, 대상·소유·공간 신호의 불일치를 찾는다(H).

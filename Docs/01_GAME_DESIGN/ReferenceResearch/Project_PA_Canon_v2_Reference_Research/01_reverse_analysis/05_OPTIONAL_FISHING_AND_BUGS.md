# 낚시·벌레: 기다림, 대상 선택, 성공의 경계

연구 대상 ACT-02. Canon §5·§21의 선택 활동이다. 핵심 루프를 완료하기 위한 강제 관문으로 바꾸지 않는다. 근거 DK-D1·DK-D2·AC-D1·AC-D2·DK-01/02. 연속 낚시 영상은 확보하지 못해 아래 원작 순서는 공식 문헌 D이다.

## 낚시에서 서로 다른 두 판단

ACNH 공식 팁은 그림자 앞에 캐스팅하고 물고기가 접근해 입질하면 입력한다고 설명한다. Dinkum 도움말은 입질을 구분해 hook한 뒤, 저항 때 릴을 멈추고 잠잠할 때 릴을 하는 반복을 설명한다(D). 전자는 입질의 구별, 후자는 입질 이후 상태 읽기까지 강조한다고 해석할 수 있다(I). 정확한 반응 윈도는 모두 U다.

|---|---|---|---|
| 대상 선택 | 무엇을 잡으려는가? | 물고기/그림자의 위치, 바라보는 방향 | 보이는 대상과 보상 종이 일치 |

## 현재 P.A.의 추가 단계는 별도 판단 대상이다

PA-R2와 코드 R: 현재 Demo256은 캐스팅·입질·미니게임 뒤 물고기를 마른 육지에 올리고, 유효 도구 접촉 2회 후 기존 DayPrepStock을 통해 종 1개를 지급한다. 가방이 가득 차면 물고기를 남긴다. 이것은 Dinkum/ACNH에서 관찰한 규칙도, Canon의 신규 의무도 아니다.

이 추가 단계에는 ‘내가 올린 물고기를 세계에서 다시 포획한다’는 물리적 장점과 ‘낚시 성공 뒤 또 다른 조작이 필요한 이유를 모른다’는 비용이 함께 있다(I). 따라서 낚싯대를 든 상태에서 도구로 전환할 이유·착지 위치·현재 성공의 뜻을 짧게 읽게 해야 한다(H). 낚시 안내와 일반 E 힌트가 겹쳐 서로 다른 동작을 가르치면 추가 단계의 비용이 더 커진다.

`FishingSpot`은 착지 때 현재 선택 instance에 `ConsumeSuccess`를 호출하고, 최종 `TryClaimLandedFish`에서 실제 재고를 지급한다(R). Canon은 물고기 실제 획득에 내구도 비용을 둔다(C). **차감 시점 정합성 검토가 필요하다.** 이 문서로 버그를 실행 재현했다고 주장하지 않는다. 낚싯대 성공의 정의·착지 후 취소·가방 부족·포획 도구의 비용을 하나의 실제 입력 실험에서 함께 기록해야 한다.

## 벌레 포획의 공정성

DK-01은 swing과 결과 제시의 포즈 차이를 보여준다(V). AC-D1은 대상 성격에 따라 정면 swing과 조심스러운 접근을 구분한다(D). P.A.에 잠입 시스템을 복사하는 대신, 보이는 대상·현재 도구·행동 방향·획득 결과가 일치하는지를 검수한다(H).

실패를 세 경우로 나누면 원인 신호를 정하기 쉽다(H). 범위 밖이면 동작은 했지만 닿지 않았음을 보인다. 도구가 틀리면 올바른 도구를 암시한다. 이미 포획되었거나 가방 부족이면 세계 대상/보상 상태를 유지하고 중복 성공 표현을 막는다. 원작의 실패 분류라는 주장은 아니다.

## 선택 활동의 품질은 부담을 덜면서 판단은 남긴다

선택 활동을 건너뛰어도 정착·개점·마감이 가능해야 한다(C). 시도했다 실패해도 필수 도구 여유를 고갈시키거나 밤을 늦추는 벌이 되어서는 안 된다(H/C 내구도). 얻은 물건은 다른 자원과 같은 가방/손/진열 문법으로 이어져야 한다. 별도 보상 가방·별도 상점 상품 생성으로 연결하면 전체 학습이 분열된다.

추가 캡처는 U-04/U-07을 우선한다. 선택 낚시의 복잡도를 늘리는 것보다, 현재 단계의 신호와 취소/보상 경계를 완성하는 것이 먼저다.

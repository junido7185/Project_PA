# ACT-01/02: 입력·손·도구·채집의 개발 계약

Canon: §1.1·§3–5·§10·§21·§23. 역분석: [Dinkum](../01_reverse_analysis/01_DINKUM_ACTION_AND_WORLD.md), [ACNH](../01_reverse_analysis/02_ACNH_LEARNING_OWNERSHIP.md), [선택 활동](../01_reverse_analysis/05_OPTIONAL_FISHING_AND_BUGS.md). 코드 근거 PA-CODE. 이 문서의 계약·실험은 H이며 Canon 고정 규칙은 C로 표시한다.

## 서로 다른 상태를 하나의 bool로 합치지 않는다

| 축 | 구분해야 할 값 H | 기존 책임 R/C |
|---|---|---|
| 입력 소유 | 세계 / UI modal / 배치 / 도착 전환 | PlayerInputHandler·각 UI·placement 기존 경로 |
| 선택 | 선택 hotbar index·실제 instance | Inventory 권위 |
| 손 | 들고 있음 / X로 집어넣음 | EquipmentSystem `IsHolstered`, `HeldItem` |
| 행동 | 준비 가능 / 시도 중 / 결과 / 회복·취소 | EquipmentSystem 표현 + 대상의 실제 작업 책임 |
| 대상 결과 | 무효 / 유효 작업 / 드롭 / 실제 지급 | Gatherable·MiningSpot·BugCritter·FishingSpot 등 기존 책임 |

선택은 남아 있지만 손은 비어 있을 수 있다(C/R). 이를 가방 비움으로 처리하지 않는다. 애니메이션 중이라도 가방 성공 여부는 별개다. 동일 E가 UI 확인과 세계 작업을 동시에 실행하지 않도록 입력 소유를 우선한다.

## 한 번의 E에서 유지할 정보

H: 입력이 수락되는 시점에 ‘행동 주체, 실제 대상, 사용 도구 instance, 행동 종류’를 연결한다. 반드시 새 저장 데이터나 범용 명령 프레임워크를 만들 필요는 없다. 기존 함수 사이에서 필요한 참조를 안정적으로 넘기는 최소 변경으로 구현한다.

동작 중 숫자 키로 도구가 바뀌었다면 기존 정책을 명확히 한다. 이미 시작한 작업을 취소하거나 시작 도구로 완료해야 한다. 접촉 순간의 현재 선택 슬롯을 무조건 다시 읽어 다른 도구에 내구도 비용을 주는 것은 피한다. 대상이 사라지면 재지급하지 않고 실패/취소로 끝낸다.

실행 순서 가설:

1. modal/전환/배치가 입력을 소유하는지 검사한다.
2. Canon 우선순위로 후보를 선택한다: 바닥 줍기 → 명시적 interactable → 유효 tool target → 자연 행동.
3. 프롬프트가 보여준 후보와 실행 후보를 대조하고 행동을 수락한다.
4. 표현을 시작하되 실제 성공 판정과 지급은 기존 대상/Inventory 권위에서 수행한다.
5. 성공의 종류에 맞는 내구도·세계 변화·실제 증가량을 확정한다.
6. 그 사실을 획득/접촉 표현에 전달하고 입력/이동을 정상 복귀시킨다.

표현을 animation event에 맞추는 것은 선택 가능한 H다. 도메인 성공을 event가 다시 호출하거나 획득 VFX가 재고를 지급하게 만들면 중복이 된다. 기존 즉시 처리 경로를 무조건 재작성할 필요는 없으며, 원인/결과의 순서와 중복 방지만 일치시킨다.

## 동작별 원인과 비용

| 동작 C | 성공을 정의하는 경계 | 비용/소유의 핵심 | 표현 H |
|---|---|---|---|
| 나무 흔들기 | 실제 나무 반응·사과 드롭 | 훈련 사과와 섬 초기 재고 분리 | 흔들림 → 드롭의 위치가 보임 |
| 바닥 줍기 | Inventory 추가 성공 | 성공 후 바닥 수량 감소/제거, 실패 시 보존 | item·실제 증가량을 알려줌 |
| 도끼/곡괭이 | 해당 자원에 유효 작업 | Canon 성공 작업만 내구도 차감, 허공/오도구 0 | 도구 방향·접촉점·대상 반응 |
| 벌레 포획 | 실제 포획/획득 | 중복 포획 방지, 실제 성공만 비용 | 휘두름과 획득 제시 구분 |
| 낚시 | 물고기 실제 획득 | 착지·최종 지급·도구별 비용 정합성 검토 | 현재 phase와 다음 입력 명확 |
| 진열 | 선택한 held 판매품이 ShopSlot로 이전 | 가방과 진열 수량/품질 보존 | 손/슬롯/모델 동시 최종 상태 |

가방이 가득 찬 경우 세계 결과와 획득을 별도 처리한다. 이미 나무에서 나온 드롭은 사라지지 않아야 하고, 아직 가방 지급되지 않은 벌레/물고기의 유지·재시도 정책은 대상 권위에서 정의한다(H). 모든 채집을 자동 성공으로 바꾸지 않는다.

## tap/hold는 행동 문법이다

C: Workbench는 짧은 E 제작, 약 0.5초 Hold E 이동. H: 누름 시작에서 대상과 빈손 조건을 잡고, release가 threshold 이전이면 tap, threshold를 통과하면 hold를 한 번 실행한다. hold 뒤 release가 tap을 다시 실행하면 안 된다. 대상 이탈·modal 열림·씬 전환·손 도구 변경은 해당 gesture를 취소하고 다음 입력을 새로 받아야 한다.

R: PlayerInteraction에는 `pendingHold`, `holdBegan`과 대상/held 검사, 0.5초 기준이 이미 있다. 새 gesture 시스템을 만들기 전에 현재 취소 경로를 보완한다. `ShopPriceUI` 등 modal에서는 세계 TryInteract가 막힌다. UI를 닫은 프레임의 동일 E가 세계 행동에 새로 전달되지 않는지는 실제 입력으로 확인한다.

## 모션·카메라·음향의 결합

H: 준비 포즈는 행동 방향을, swing은 도구 궤적을, 접촉은 세계 반응을, 획득은 물건 identity를 설명한다. 손이 도구 손잡이에서 미끄러지거나 발이 지면 위에서 움직이면 실제 작업의 무게가 약해진다. 카메라는 캐릭터만 보이는 것보다 대상과 앞 칸이 같이 보여야 한다. 기본/근접 시점 둘 다 확인한다.

SFX 가설은 swish=시도, contact=유효한 접촉, acquire=실제 지급으로 구분한다. 같은 소리를 무조건 모두 성공 신호로 쓰지 않는다. 사운드 수치는 원작에서 측정하지 않았다. 기존 AudioManager 풀·설정·mute 경로에서 검증한다. camera shake/멈춤/입자 추가는 명확성을 개선하는지 실제 입력에서 판단하며 필수 효과로 지정하지 않는다.

이 시나리오는 구현 후 수행할 검수이며 이번 연구의 실행 PASS가 아니다. 원작 리치·쿨다운·애니메이션 duration은 U-01/U-07 관찰 전에는 복제하지 않는다.

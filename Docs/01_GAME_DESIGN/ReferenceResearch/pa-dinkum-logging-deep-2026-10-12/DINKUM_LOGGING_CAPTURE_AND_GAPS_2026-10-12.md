# Dinkum 벌목 — 미확인 항목과 추가 확보할 장면

**기존 OPEN_QUESTIONS의 U-01은 OPEN으로 유지한다.** 나무 반복 동작의 시각적 부분만 일부 확인했고, HUD·원본 음향을 갖춘 벌목 완료 사례는 확보하지 못했다. 바위/채광 부분은 이번 연구 대상이 아니며 미해결 상태를 그대로 둔다.

## 1. 정확히 남은 질문

| 하위 ID | 미확인 U | 이를 알아야 하는 이유 | 필요한 최소 증거 |
|---|---|---|---|
| U-01-T01 | 발견·접근·정렬·도구 선택 | 조작감은 첫 타격 전에 시작함. 어느 나무를 골랐는지와 손 모델의 약속 | 나무를 발견하기 전 화면부터 접근·hotbar 변경·손의 도끼까지 무편집 |
| U-01-T02 | 입력 수락·허공·오도구·유효 시도 | 시작 반응과 실제 작업의 차이, 실패 학습 | 실제 입력 표시, 같은 도구/나무에서 유효·무효 시도, 전체 HUD |
| U-01-T03 | 반복 입력·홀드·버퍼·회복·이동 해제 | 미디어의 반복 표식 간격과 입력 가능 시간을 분리 | 누르기/놓기 표시, 타격 중 방향 전환/이동/다음 입력의 연속 기록 |
| U-01-T04 | 실제 유효 작업과 비용·스태미나 변화 | 접촉 효과가 성공 상태인지 확인 | 해당 도구/나무 조건, 보이는 HUD 전후. 상태 표식이 없으면 미확인 유지 |
| U-01-T05 | 몸·발·그립·도구 궤적의 일반 플레이 품질 | 홍보 구도에서 본 자세를 실제 이동-벌목 연결로 일반화하지 않음 | 발·손·줄기가 충분히 보이는 정상 플레이 카메라, 접근부터 타격·이동까지 |
| U-01-T06 | 나무 고유 hit 반응과 최종 소진 | 환경 흔들림과 hit 반응 구분, 일반/마지막 타격의 차이 | 같은 나무의 첫/중간/최종 작업을 이어서 기록. 잔여 오브젝트가 있다면 후속 상태 포함 |
| U-01-T07 | 목재 생성·수량·위치·착지·획득 방법 | 세계 결과와 Inventory 지급의 경계 | 최종 작업부터 드롭 안정화·줍기·가방 전후·다음 이동까지 무편집 |
| U-01-T08 | 원작의 실제 소리와 상대 시점 | 공기 이동·접촉·소진·착지·획득을 각각 판독 | 원본 게임 음향이 들리는 같은 연속 구간. 해설/배경음 혼합 여부 기록 |
| U-01-T09 | 가방 부족·부분 추가·재시도 | 실패가 자원/보상/일상 복귀를 어떻게 처리하는가 | 가방 부족 상태에서 목재 생성/줍기→공간 확보→같은 드롭 재시도 |
| U-01-T10 | 도구 변경·파손·대상 이탈·중단 | 한 동작이 어느 도구/대상의 작업인지 유지하는가 | 동작 단계별 도구 변경과 실제 결과, 마지막 타격/파손이 겹치는 연속 사례 |
| U-01-T11 | 게임 플레이 카메라·가림 처리 | 홍보용 cut/track을 실제 follow/obstruction으로 오인하지 않음 | 기본 구도와 실제 카메라 입력이 표시된 가림 구간 |

공개 영상에 입력 표시가 없으면 T02/T03의 입력 시점은 계속 U다. Inventory 전후가 없으면 목재가 사라졌다는 화면만으로 T07의 실제 증가량을 확정하지 않는다. 소리가 혼합되어 분리되지 않으면 T08의 특정 효과음을 ‘확인’으로 올리지 않는다.

## 2. 가장 먼저 확보할 한 편

**일반적인 도끼와 나무의 정상 벌목을 시작부터 끝까지 보여주는 원속도 연속 플레이 한 편**이 가장 가치가 크다. 나무를 발견하고 접근, 도구 선택, 첫 타격, 비최종 반복, 최종 소진, 목재 생성, 획득, 다음 이동이 한 시간축에 있어야 한다. 가능한 HUD 전체와 원본 게임 음향을 보존한다.

이 장면 한 편이 없으면 더 많은 예고편과 도구별 숫자표를 모아도 전체 벌목의 경험 구조를 검증하기 어렵다. 기존 후보 DL-Q01–04는 접근 가능한 원본/녹화 파일이 확보되면 다시 선별할 가치가 있지만 **아직 정확한 벌목 구간 시간을 확인하지 못했다.**

## 3. 이후 필요한 최소 비교 세트 H — 캡처 설계

아래 횟수는 연구를 위한 권장 표본이며 Dinkum의 작업 횟수나 타이밍이 아니다.

| 우선 | 장면 | 통제·비교 | 해결하는 질문 |
|---|---|---|---|
| 1 | 정상 벌목 전체 1회 | 같은 영상 안에 접근·선택·HUD·원음·획득·다음 행동 | T01·04·06·07·08 |
| 2 | 같은 도구/같은 종류의 나무로 완료 사례 추가, 가능하면 총 3회 이상 | 도구 등급·나무·버프·스태미나 조건을 기록. 화면에 없는 값은 불명 | 타격 위상과 완료 시간의 반복성, 편집/우연 구별 |
| 3 | 정상 타격과 허공/잘못된 대상, 실제 입력 표시 | 동일한 도구와 기본 카메라. 입력을 개별 누름/홀드로 명시 | T02·03. 효과와 성공의 관계 |
| 4 | 준비/앞쪽 동작/회복 중 이동·도구 변경 | 변경한 시점과 버튼이 보임. 일부는 계속 같은 나무, 일부는 이탈 | T03·05·10 |
| 5 | 최종 소진부터 목재 획득, 가방 부족/부분 공간 포함 | Inventory 전후·바닥 잔량·재시도. 실제로 부분 추가가 지원되는지는 관찰 후 판정 | T07·09·10 |
| 6 | 기본 시점과 줄기/풀 가림 조건 | 실제 카메라 입력과 구도 변경을 기록 | T05·11. 접촉/드롭 가독성 |

원작의 모든 도구·나무·바이옴을 조사하지 않는다. 기본 벌목의 원리를 이해한 뒤, 조건 차이가 그 원리를 바꾸는지를 확인하는 최소 비교에 집중한다.

## 4. 파일/캡처 수용 기준 H

- 가능하면 1920×1080 이상, 고정 캡처 FPS와 원본 영상 파일을 확보한다. 60 fps 캡처가 가능하면 작은 시각 경계를 좁히기 좋지만, 실제 게임 FPS와 혼동하지 않는다.
- 전체 행동의 앞뒤를 자르거나 speed-up/slow-motion 하지 않는다. UI/소리/선택 동작을 위해 컷을 넣었다면 원본 시간 연결을 별도 기록한다.
- HUD 전체, 발·손·도구·줄기·드롭을 가능한 한 보존한다. 해당 게임에 없는 바/표시를 새로 있다고 가정하지 않는다.
- 게임 빌드, 플랫폼, 도구 등급, 나무 종류, 모드/플레이 설정, 해설·추가 음악·음소거·오디오 지연 여부를 기록한다. 입증할 수 없는 값은 ‘불명’으로 둔다.
- 입력 표시는 녹화 화면과 같은 시간축이어야 한다. 표시 지연/캡처 지연이 알려지지 않으면 버튼→화면 변화 수치를 정밀 입력 지연으로 발표하지 않는다.
- 원본 음향을 보존한다. 오디오 트랙 존재뿐 아니라 실제 신호가 있는지 검사하고, 청취로 사건 의미를 판독한다. 파형 peak만으로 타격/목재/획득 이름을 붙이지 않는다.

## 5. 영상 확보 후의 프레임 분석 절차 H

1. 파일 해시·해상도·영상/음향 스트림·PTS·재생 속도/편집을 기록한다. 먼저 전체 완료 사례를 원속도로 보고 사건 순서를 적는다.
2. 발견/접근·선택·첫 움직임·접촉 표시·대상 상태 변화·반복·최종 소진·생성·착지·획득·다음 행동의 **서로 다른 표식**을 표시한다.
3. 각 경계 주변을 인접 프레임으로 판독한다. ‘마지막 부재/첫 존재’와 가림/모호함을 함께 기록한다. 원본 n과 PTS를 쓰고, 추출 PNG 연번을 원본 프레임 번호로 쓰지 않는다.
4. 음향을 같은 구간에서 청취하고 시작·끝·겹침을 표시한다. 믹스에서 분리되지 않으면 ‘혼합/미분리’로 유지한다.
5. 실제 상태의 근거를 따로 붙인다. 효과, HUD 변화, 드롭, Inventory 증거가 서로 지지하는지 확인한다. 입력 표시가 없으면 입력 시점은 측정하지 않는다.
6. 반복 사례는 각 타격의 같은 시각 표식을 기준으로 정렬한다. 준비·앞쪽 움직임·접촉/효과·회복·실제 다음 입력의 간격을 각각 비교한다. 파일 FPS를 동작 프레임 수/엔진 tick으로 바꾸지 않는다.
7. 원작의 만족도가 왜 성립하는지 I로 설명하고 대안 설명/반례를 붙인다. P.A. 적용은 H로 작성하고 기존 Q-DL 검수와 연결한다.

## 6. U-01 나무 부분을 닫을 조건

핵심 정상 완료 사례의 HUD·원음·전후 연속성이 확인되고, 반복/무효 시도/획득의 주요 분기가 직접 근거로 설명되어야 한다. 입력 gate와 내부 구현은 끝까지 관찰할 수 없는 항목일 수 있으며 그 경우 독립 U로 남긴다. 내부 코드가 없어도 화면·입력·소리·실제 상태 변화가 어떤 순서로 연결되는지는 근거 있는 자료로 작성할 수 있다.

이번 결과는 그 조건을 충족하지 않는다. **검색 결과의 제목, 공식 예고편의 컷, 52프레임이라는 숫자만으로 U-01을 종료하지 않는다.** 추가 자료가 들어오면 이번 문서에 새 출처/장면/판정을 보충하고 기존 O/M/H를 소급해서 혼합하지 않는다.

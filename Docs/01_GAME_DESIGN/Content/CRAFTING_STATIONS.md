# 용도별 작업대와 제작 콘텐츠 (데모 첫날 경로)

작성 2026-11-02 · 근거 요청: PA_CONTENT_DEPTH_20261026_V1("작업대에서 만들 게 너무 적다, 딩컴처럼 용도별 작업대, 쓸데없는 생산물"), 2026-11-02 "크래프팅 요소 세분화·콘텐츠 설계 및 제작"
상위 권위: Opening Demo Canon v2 §8 Utility("향후 제작 설비 가능"), §9 Placeable 공통 문법, §10 Workbench. 이 문서는 그 범위 안의 데모 콘텐츠 정의다.

## 1. 원칙

1. **작업대는 용도로 나눈다.** 같은 기능을 여러 작업대에 복제하지 않는다. 새 작업대는 '할 수 있는 일'을 늘린다.
2. **모든 산출물은 쓰임이 있다.** 판매·설치·다른 레시피의 재료·도구(교체/상위)·동료 선물 중 하나 이상. 제작 창 상세의 '쓰임'이 실제 데이터에서 이를 보여 준다.
3. **데모에서 얻을 수 없는 재료의 레시피는 숨긴다.** 첫날 경로는 농사를 끄므로 밀·당근·씨앗 레시피(빵·구운 감자·의류)는 보이지 않는다. 등급 잠금(목제 가구·철제 도구)은 성장 신호라 보인다.
4. **작업대도 배치물이다.** 조리대·화로는 현장 작업대에서 '키트'로 만들어 같은 핫바 배치 문법으로 놓는다(Furniture 종류, 2×1칸, 개수 제한 없음).
5. 새 저장 스키마는 없다. 배치는 `demoSession.placedBuildings`(키 `field-kitchen`/`field-forge`), 아이템은 id로 저장된다.

## 4. 한 바퀴(첫날 기준)

나무 베기·바위 캐기 → 현장 작업대에서 판재 → 조리대·화로 키트 → 정착지에 배치 →
낚시(반복) → 조리대에서 생선구이 / 나비 → 액자 / 광석 → 철괴 → 철 도구 →
해 질 녘 가판대에 생선구이·액자 진열 → 밤 영업 판매(관광객은 Luxury 선호) · 닳은 도구는 철 도구로 교체.

## 5. 경제·검증 메모

- 생선구이 1개 +34G 정도, 하루 반복 낚시로 판매 상한(관광객 최대 7명/영업)이 실제 총액을 제한한다. Pioneer Report Commerce 매출 항목은 120G에서 만점이라 랭크가 쉽게 오를 수 있다 — 실제 플레이 뒤 조정.
- 광석은 키트(2+4)·철괴(2개당 2)·개선 곡괭이(2)가 나눠 쓴다. 바위 1개 = 광석 3.
- 새 레시피는 `Resources/DemoStructure`에 둔다(Basic 레시피 수를 세는 기존 검증기 보존). 생성: `PA_CraftingStationsSetup.Apply`(멱등, id·이름 충돌 시 실패), 모델: `PA_StationArt.ApplyToStations`.
- 격리 촬영 검증: `-pa-capture-plan crafting` (작업대 → 키트 → 실제 핫바 배치 → 조리대·화로 제작 → 도감 → 전경).

# 가게 러그 바꾸기 (너굴 리스트 연구 H5 일부)

2026-11-09 추가. 연구 H5(탁자 위·벽 장식·러그) 중 **러그 교체**만 먼저 구현했다. 탁자 위·벽 장식은 배치 점유와 저장 형식 결정이 필요해 보류.

## 규칙
- 아이템: 해초 러그(2060) = 해초 3, 산호 러그(2061) = 산호 조각 1 + 해초 1. 현장 작업대에서 만든다.
- 사용: 러그를 들고 가게 실내의 생활 러그 위에서 [E] `러그 바꾸기 · {이름}`. 러그 색(LivingRug·RugInner·RugStripeA/B)만 바뀐다.
- 새 물건을 놓는 것이 아니라 이미 깔려 있는 러그의 무늬만 바꾼다. 배치 칸 점유 규칙(칸당 하나)은 바뀌지 않는다.
- 바꾸면 깔려 있던 러그는 가방으로 돌아온다. 처음 깔려 있던 기본 러그는 아이템이 아니어서 돌려주지 않는다.
- 같은 러그를 다시 깔려고 하면 "이미 … 깔려 있어요."라고 안내하고 아이템을 쓰지 않는다.
- 러그를 들고 있을 때만 [E] 대상이 된다. 빈손일 때는 다른 실내 상호작용을 가리지 않는다.

## 저장
- `SaveData.shopRugStyle`(추가 필드, "" / "seaweed" / "coral"). 옛 저장은 비어 있어 기본 러그로 열린다.
- 이어하기: `SaveManager`가 `ShopRugSwap.Pending`에 넣고, 실내가 생기면 칠한다.

## 구현 메모
- `World/ShopRugSwap.cs`: 운영 중인 가게(`DemoSettlementController.OperatingShop`)의 실내에 묶는다. 러그를 든 동안 [E] 지점이 '플레이어 바로 앞 러그 위'로 따라온다. 러그 한가운데에 지점을 고정하면 러그 위 탁자에 가려 선택되지 않았다.
- `PlayerInteraction.ResolveInteractable`은 `ShopRugSpot`을 먼저 해석한다. 러그 지점은 가게 배치물의 자식이어서, 그대로 두면 가게(`DemoPlacedObject`)로 풀린 뒤 '든 물건' 조건 때문에 건너뛴다.
- 칠하기는 그 러그의 `renderer.material`만 바꾼다. 공용 재질은 통로 러너도 함께 쓰기 때문이다.
- 캡처: `-pa-capture-plan rug`. 러그 두 장 짜기 → 실내 → 해초 → 산호 → 해초 러그 돌려받음 → 저장·이어하기 뒤 산호.

## 검증
- r205 rug ok: 안내 `[E] 러그 바꾸기 · 해초 러그`, 기본→해초→산호(swaps 2). 해초 러그가 가방으로 돌아왔고 이어하기 뒤 coral이 유지됐다. 화면 3장에서 청록→초록→분홍을 확인했다.

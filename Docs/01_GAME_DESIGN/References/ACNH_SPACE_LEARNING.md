# Animal Crossing — 내가 바꾼 공간과 자연스러운 배움

근거: [S-AC1, R-02, R-05](SOURCE_REGISTER.md). 개발자 설명과 P.A.의 해석을 구분한다. 원작의 세부 배치 알고리즘·셰이더·카메라 수치는 미확인이다.

## AC-01 — 공간 변경을 플레이어의 소유감으로 연결한다

- **D:** 개발진은 기존 주민이 사는 마을 대신 무인도에서 시작해 플레이어와 동물의 관계를 새롭게 만들고자 했다고 설명한다(S-AC1).
- **I:** 정착 과정을 플레이어 행동의 결과로 읽게 하는 것이 P.A.에 유효하다. 이는 원작의 모든 지형 편집 기능을 가져오자는 뜻이 아니다.
- **P:** Shop/Base·동행 텐트·진열의 전후 차이가 실제 공간에 남게 한다(Canon §7~12). 배치 미리보기는 실제 footprint·pivot·회전·입구·접근 가능성을 약속해야 한다. 미리보기 판정과 commit은 기존 배치 권위를 공유한다. 취소하면 ghost·입력 상태가 끝나고 원본 인스턴스·재고가 보존된다. OPEN 중 이동 같은 현재 금지 상태는 그대로 지킨다.
- **연결/완료 모습:** WorldBuildingPlacementService·WorldNavigationService·WorldPersistenceService. UI만 숨겨 preview를 남기지 않고, 저장을 위해 별도 배치 데이터 권위를 만들지 않는다. 완성 게임의 판매→마을 변화 방향은 유지하되 데모에 다음 날 기능을 추가하지 않는다.
- **다시 열 조건:** preview와 실제 배치 불일치, 취소 후 유령/손실, 출입/주민 접근 차단, 배치 계약 변경.

## AC-02 — 할 수 있는 행동을 발견하게 한다

- **D:** 개발진은 Nook Miles가 다양한 놀이를 발견하게 하고 흔한 활동에도 의미를 주도록 설계했다고 설명한다(S-AC1).
- **I:** 초보자는 방대한 설명보다 지금 할 수 있는 행동과 결과를 통해 루프를 배울 수 있다. 효과의 크기나 플레이어 반응을 인터뷰만으로 입증한 것은 아니다.
- **P:** P.A.는 현재 입력·대상·직전 결과에 맞는 짧은 안내를 쓰고 지나간 정보는 휴대폰 기록으로 돌린다(Canon §18·§22). 채집→진열→가격→OPEN→반응 중 막힌 연결을 알려준다. 상시 퀘스트 목록, 새 Miles 보상 체계, 추천가/구매확률 답안 UI를 추가하지 않는다. 보호된 SmartphoneUI 변경은 기존 승인 계약을 따른다.
- **연결/완료 모습:** 기존 onboarding/presentation/Phone 기록. 성공 토스트는 실제 사건 뒤에만, 안내 종료 뒤에는 다음 입력과 대상이 읽혀야 한다. 원본 코드의 reason enum을 플레이어 안내로 그대로 노출하지 않는다.
- **다시 열 조건:** 실제 플레이에서 다음 행동을 찾지 못함, 안내 겹침/오안내, Canon의 HUD 방향 변경.

## AC-03 — 장식보다 생활의 가독성을 먼저 만든다

- **O:** 기존 공간/표현 역분석은 보행 여백·오브젝트 간 간격·입구·실루엣·반응의 읽힘을 P.A. 관찰 기준으로 정리했다(R-02, R-05). 이 항목들의 개발자 직접 설명은 확보하지 못했다.
- **I/P:** 현지 자산의 큰 형태·색 역할·축척을 통일하고, 상호작용 대상 앞과 NPC 통로에는 여백을 둔다. 주민이 어디로 가서 무엇을 하는지 정상 카메라에서 보이게 한다. 낮의 탐색과 밤의 영업에 서로 다른 조명 분위기를 주되 가격·상품·말풍선의 판독을 유지한다. [Style Grammar](../Art/PROJECT_PA_ART_STYLE_GRAMMAR.md)의 수치 제안은 P.A.의 출발값이며 원작에서 측정된 공식이 아니다.
- **연결/완료 모습:** 기존 CameraController·presentation·로컬 자산. 이름표·디버그 표시를 늘려 빈 공간이나 잘못된 구도를 가리지 않는다. ACNH의 카메라/외형을 그대로 고정하지 않는다.
- **다시 열 조건:** 실제 GameView에서 대상/주민/동선이 가려짐, 자산 계열 충돌, 낮밤 판독성 차이.

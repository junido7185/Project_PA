# Dave the Diver — 반복 행동의 감각과 짧은 성취

근거: [S-DV1, R-05](SOURCE_REGISTER.md). 개발자 선택의 맥락과 P.A. 적용을 구분한다. 원작의 컷신 길이/성공 연출 수치를 측정한 문서가 아니다.

## DV-01 — 가장 자주 하는 행동에 제작 우선순위를 둔다

- **D:** 개발진은 핵심 작살 행동의 감각을 먼저 다뤘고, 2D만으로는 수중 깊이가 부족해 3D 배경을 결합했다고 설명한다(S-DV1).
- **I/P:** P.A.에서는 실제 이동·도구 접촉·줍기·배치·가격 결정의 연결을 우선한다. 현재 승인 경험의 실제 손/발/대상/보상 차이를 고친다. 데코·새 콘텐츠 수를 늘려 반복 행동의 결함을 덮지 않는다. Dave의 표현 방식을 이유로 3D 게임을 2D 혼합으로 전환하거나 렌더링 구조를 바꾸지 않는다.
- **연결/완료 모습:** 기존 PlayerController·EquipmentSystem·presentation과 로컬 애니메이션/자산을 재사용한다. 모션은 연속 입력/영상 근거로 판단하며 정지 포즈의 수치만으로 손맛을 확정하지 않는다.
- **다시 열 조건:** 실제 반복 행동의 판독/접촉/입력 복귀 문제, 또는 핵심 활동 변경 승인.

## DV-02 — 낮밤 모두 플레이어가 참여할 이유를 둔다

- **D:** 개발진은 초기에 자동으로 돌아가던 초밥집에서 플레이어와의 연결이 약해, 직접 캐릭터를 조작하는 방식으로 바꾸었다고 설명한다. 캐릭터가 시스템을 자연스럽게 소개하게 한 방향도 설명한다(S-DV1).
- **I:** 자동 처리의 양보다 플레이어가 무슨 판단을 하는지가 두 모드의 연결을 만든다.
- **P:** 낮에는 손으로 준비하고 밤에는 상품·가격·OPEN/CLOSE와 실제 고객 반응을 자신의 결과로 읽게 한다. 기존 자율 구매는 유지한다. Dave처럼 직접 음식 서빙하는 미니게임을 추가하지 않는다. 안내는 현재 인물/상황/행동에 연결하되 새 NPC나 대사 시스템을 자동 확장하지 않는다(Canon §18·§22).
- **연결/완료 모습:** 현재 낮 준비→영업 MUST PATH와 기존 NPC/상점 권위. 영업 중 플레이어 역할이 불명확하면 현재 승인 동작의 정보/피드백을 먼저 개선한다.
- **다시 열 조건:** 실제 플레이에서 낮밤이 서로 무관하게 느껴지는 구체적 원인, 영업 역할 재설계에 대한 사용자 승인.

## DV-03 — 성취를 보여주고 조작권을 정확히 돌려준다

- **O:** 기존 연출 역분석은 짧은 집중 → 성취의 규모/의미 → 실제 조작 복귀라는 P.A. 적용 구조를 정리했다(R-05). 이 길이와 순서를 원작 개발자의 직접 지시로 인용하지 않는다.
- **P:** 항해 8~12초는 **P.A. Canon §1.3의 계약**이다. 첫 판매·CLOSE·Pioneer Report는 실제 사건 뒤 한 번 보여주고 입력·카메라·시간을 기존 소유자에게 돌려준다. Report의 건수/금액/평가/2~4개 코멘트는 Canon §20과 실제 로그를 사용한다. 런타임 LLM 없이 기존 규칙 기반으로 만들며, 생성형 문장으로 없는 성취를 만들어내지 않는다.
- **연결/완료 모습:** 기존 opening/FirstDayWorldPresentation·GameClock·SalesLog·Report. 재진입·닫기 뒤 입력이 남거나 전환 중 판매를 중복 확정하지 않게 한다. 범용 컷신 프레임워크·새 패키지를 만들 이유로 삼지 않는다.
- **다시 열 조건:** 실제 로그와 Report 불일치, 중복 재생, 닫은 뒤 입력/시간 미복구, 연출 계약 변경.

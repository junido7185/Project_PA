# Dinkum — 손으로 하는 행동과 일관된 세계

근거: [S-DK1, S-DK2, R-01, R-02, R-03](SOURCE_REGISTER.md). `D/O/I/P` 구분은 [입구](README.md) 참조. 원작 내부 코드·정확한 카메라/모션 수치는 확인하지 않았다.

## DK-01 — 화면의 대상과 실제 행동 대상을 일치시킨다

- **D:** James Bendon은 낚시에서 보이는 물고기가 실제 잡는 물고기이기를 원했고, 도전은 있으나 불필요한 좌절은 줄이고 싶었다고 설명한다(S-DK2).
- **I:** 보이는 단서와 실제 결과가 다르면 플레이어는 행동의 규칙을 학습하기 어렵다. 이 해석을 낚시 밖의 P.A. 상호작용에도 적용한다.
- **P:** 프롬프트 대상과 실행 대상은 같은 기존 선택 권위를 사용한다. E·도구·줍기 우선순위는 Canon §4~5와 현재 입력 계약을 따른다. 나무 옆 떨어진 사과를 줍는 안내가 뜨면 나무 타격을 실행하지 않는다. 도구 선택·그립·접촉·보상이 동일한 대상을 설명해야 한다.
- **연결/완료 모습:** PlayerInteraction·EquipmentSystem·기존 target 인터페이스를 재사용한다. 허공/잘못된 도구/가득 찬 가방은 성공 획득으로 표시하지 않는다. 원작의 낚시 미니게임을 새로 추가하라는 결정이 아니다.
- **다시 열 조건:** 프롬프트와 실제 대상이 어긋난 실제 사례, 또는 입력/대상 우선순위에 대한 사용자 변경.

## DK-02 — 행동의 성공과 보상 지급을 구분한다

- **O:** 기존 채집 역분석은 준비 → 시도 → 유효 접촉 → 월드 결과 → 드롭/줍기 → 인벤토리 반영을 구분했다(R-01, R-03). 짧은 참고 영상만으로 이 전부의 자연 연속 실행이나 원작의 내부 지급 순서를 증명한 것은 아니다.
- **I:** 효과를 먼저 재생하고 뒤에서 실패하면 화면이 거짓 약속을 한다. 손맛과 거래 무결성을 같은 사건에 연결한다.
- **P:** 시도·실패·타격 성공·획득 성공 피드백을 구별한다. 기존 target이 자원/드롭을 책임지고 Inventory가 실제 수용을 확정한다. UI/장비 계층에서 보상을 중복 지급하지 않는다. 타격음은 유효 접촉, 획득 숫자는 실제 반영에 연결한다. 실패 스윙의 승인된 동작은 유지하되 성공음·보상으로 포장하지 않는다.
- **연결/완료 모습:** PlayerController·EquipmentSystem·기존 채집 target·Inventory 경로에서 손/발/도구/대상의 접촉이 읽히고 수량이 실제 결과와 맞는다. 정확한 타격 프레임·히트스톱은 원작에서 가져온 상수가 아니다.
- **P.A. 적용 — 2026-10-22:** 월드 결과의 표시 전용 산출물(벤 나무 자리의 stump)은 소진이 확정된 순간 보여 주고, 보상 수령·저장은 기존 Claim 경로(줍기 성공 후 `ClaimDirectDrop` → `SetResourceState`)에 둔다. 쓰러짐 연출이 끝날 때까지 산출물을 미루면 결과가 늦게 생기는 공백이 남는다: [r7](../../../Logs/ParallelProduction/CodexResume-20261011/MotionNative/conifer-r7-fixture-20261022/r7-frames.csv)은 f116–153 공백 후 f154 등장, `Gatherable.cs` 한 조건 수정 뒤 [r8](../../../Logs/ParallelProduction/CodexResume-20261011/MotionNative/conifer-r8-stump-fixture-20261022/r8-frames.csv)은 f102부터 유지(같은 QA fixture·30 game-fps, [지원 비평](../../../Logs/ParallelProduction/Production-observer-codex-20261020/canopy-support/r8-codex-critique.md)). 드롭 수 9→10은 오브젝트 수일 뿐이며, 보상 정확히 1회 수령·저장 복원·정상 입력·측면 접지는 미검증이다.
- **다시 열 조건:** 중복/유실 보상, 가득 참 성공 표시, 실제 접촉과 피드백 시점의 불일치.

## DK-03 — 자산 수보다 세계의 어휘와 공간 연결을 맞춘다

- **D:** Bendon은 호주 풍경을 보고 나무·주택·물탱크 등의 방향을 바꾸었으며, 테이블 위 실물을 직접 두는 Animal Crossing의 표현을 좋아했다고 설명한다(S-DK1).
- **O:** 기존 월드 역분석은 자산 계열·접지·군집과 여백·해안 경계·낮밤 가독성·일반 카메라·기능적 소군집·월드 변경 비용을 관찰 축으로 사용했다(R-02). 이것은 원작 개발자의 공식 8원칙이 아니다.
- **P:** P.A.의 섬 정착/잡화점 어휘로 기존 로컬 자산을 조합한다. 문·진열·작업대와 이동 경로가 연결된 작은 생활 군집을 먼저 완성한다. 바닥 접촉·축척·재질을 맞추고 길/광장 여백을 남기며, 해안·고지대·숲은 정상 플레이 카메라에서 구별되게 한다. 밤에도 가격·고객 반응·문이 읽혀야 한다. 장식으로 NPC 통로를 막거나 승인 없이 경사로를 추가하지 않는다.
- **연결/완료 모습:** [Style Grammar](../Art/PROJECT_PA_ART_STYLE_GRAMMAR.md)와 기존 월드/배치/NavMesh 권위를 따른다. 프리미티브 수 증가·나무 대량 배치·고해상도 텍스처만으로 밀도를 대체하지 않는다. 호주 미술·동일 건물 외형은 복제 대상이 아니다.
- **다시 열 조건:** 정상 카메라의 길 찾기 실패, 밤 영업 가독성 저하, 배치로 인한 NPC 접근 불가, 새 아트 방향 승인.

### DK-03 물가 검수에서 재사용할 판단 — 2026-10-20

- **O — P.A. 관측:** [v16 독립 검수](../../../Logs/ParallelProduction/World-v16-edge-verifier-20261020/HANDOFF.md)는 coast의 밝은 크림선은 개선됐으나 수면의 유리 같은 띠는 PARTIAL, north shore는 개선 입증 부족으로 구분했다. `after-v16-coast`의 HUD·식생 누락도 비교 조건의 문제로 남겼다. 이는 원작 내부 구현에 대한 관측이 아니다.
- **I — 원인 분리:** 물가의 밝은 선을 거품 하나로 단정하지 않는다. 지형 옆면 색과 젖은 윗면의 대비, 수중 면의 투과, water shader 거품 띠를 나눠 현재 코드·전체 화면·확대 화면을 대조한다. HUD·식생·카메라 조건이 다르면 재질 수정의 개선/퇴행과 캡처 조건 차이를 구분한다.
- **P — 수정과 재사용:** 실제 원인으로 확인된 표현 계층만 조정하며 셀·저장·충돌·NavMesh 권위를 유지한다. 이번에는 검수의 milky foam 지적을 `PA_StylizedWater.shader`의 `bandFoam` 억제에 반영했다. 이 수치나 정지 화면의 인상을 다음 해안의 고정 상수·동작 검증으로 일반화하지 않는다. 기존 `Native Production Input Session`, `ShaderUtil` 메시지 조회와 screenshot 경로를 재사용한다.
- **비교·수락:** 기존 arrival/coast/north shore의 같은 위치·카메라·시각·해상도와 HUD·식생 표시 조건을 먼저 맞춘다. 이번 fixture(09:21, FOV40, 1920×1080)는 자연 플레이와 구분하고 전체 화면과 물가 확대 화면을 함께 본다. shader 오류0은 화면 수락이 아니며 정지 이미지만으로 물결 동작을 판정하지 않는다. [보존된 v16/v17 이미지](../../../Logs/VisualQA/DinkumWorld-20261009/)와 [실제 읽기→수정→검증→v17b 캡처 연결](../../../Logs/ParallelProduction/Production-observer-codex-20261020/HANDOFF.md)을 먼저 인수하고 확인만을 위해 게임 작업을 반복하지 않는다.
- **현재 한계(2026-10-21 실제 r3 인수):** 같은 fixture의 v17c/v18b에 대한 [r3 독립 검수](../../../Logs/ParallelProduction/World-v17c-v18b-verifier-r3-20261021/HANDOFF.md)는 사각 수색 계단 개선과 함께 수중 바위 어두워짐/흐림·해초 halo 퇴행을 확인했다. soil ring/coast band는 PARTIAL이며 밤·이동·16탭 비용은 미검증이다. v19 arrival 셀 수 증가는 dressing과 dune mask가 묶여 흙 테두리를 늘려 owner가 반려·복원했다. 문서 반영 전의 v17c/v18b/v19 판단은 후속 재사용 근거가 아니다. 원본 채택은 owner componentReview에 있고, 다음 실제 물가 수정의 적용/결과와 사람 수락은 별도로 남긴다.
- **P — 작은 방법 개선:** 이번 r3의 원인 가설을 기존 shader 코드와 맞춰, 깊이 색 전이의 완화와 수중 물체 보존을 같은 north shore/coast 전체 화면·확대 crop에서 함께 비교한다. 새 절차/validator를 만들지 않고 기존 fixture·카메라·ShaderUtil·캡처를 재사용한다. 화면이 부드러워졌다는 한 항목으로 퇴행을 덮지 않는다. 수치 후보는 P.A. 현재 코드의 실험값이며 원작/GDAS 기본값이나 확정 해법이 아니다. 실제 수정 파일·같은 조건 결과·남은 차이가 있어야 이번 적용 근거로, 다른 후속 작업에서 결과를 낸 기록이 있어야 개선한 방법의 재사용 근거로 삼는다.

## DK-04 — 제안된 기능 대신 그 기능으로 해결할 필요를 찾는다

- **D:** Bendon은 상자 이동 요구를 게임에 맞는 손수레 행동으로 풀었다고 설명한다(S-DK2).
- **I/P:** 새 도구·자동화 요청은 먼저 플레이어의 막힌 행동을 특정한다. 기존 상호작용·배치·운반 표현으로 해결할 수 있으면 그것을 확장한다. NPC 지원은 직접 생활을 풍성하게 해야 하며, 낮의 준비를 완전히 없애는 자동 수급은 [Design Intent](../Creative/PROJECT_PA_DESIGN_INTENT.md)와 대조한다. 손수레 자체를 신규 티켓으로 추가하지 않는다.
- **다시 열 조건:** 실제 반복 작업의 피로 근거 또는 사용자 기능 승인. 해결할 필요가 확인되기 전에는 새 프레임워크 조사를 시작하지 않는다.

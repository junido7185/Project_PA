## 2. 판정 기준 (새 도구·대체품)
하나라도 걸리면 **비권장**이다.
1. 기존 제약 위반: 로그인 상태의 Instagram 자동 수집, YouTube 다운로드·스크래핑, 계정 한도 우회, 타 게임 바이너리 분석, 딩컴 실행, 결제, 외부 공개.
2. 거부된 설치를 우회하게 되는 경우(예: yt-dlp를 의존성으로 함께 깔아 버리는 도구).
3. 라이선스 문제: 비상업 전용, 한국 제외, AGPL을 게임에 넣는 경우, 출처가 불명확한 자산.
4. 원격 스크립트를 바로 실행하는 설치 방식(`irm … | iex`, `curl | sh`)이면서 출처 검증이 안 된 경우.

통과한 도구는 다음 점수로 **도입 / 전시 뒤 검토 / 불필요**를 정한다.
- **실제 이득:** 지금 쓰는 도구보다 무엇이 나은지 측정할 수 있어야 한다(속도, 토큰, 품질, 자동화 범위). 별 수나 SNS 주장은 근거가 아니다. 예를 들어 "토큰 −45%"류 주장은 직접 재 본다.
- **겹침:** 기존 도구(Serena, impeccable, 내장 브라우저, `/loop`, handoff 문서)와 역할이 같으면 불필요다.
- **상시 비용:** 플러그인·스킬은 켜 두기만 해도 스킬 설명 예산을 쓴다. 훅은 모든 세션과 하위 작업자에게 붙는다. 상시 비용이 이득보다 크면 프로필(`.claude/profiles/`)에 넣고 필요할 때만 켠다.
- **충돌:** 단일 Unity writer, 하위 작업자 훅 비활성화, loop-state/supervisor, 세이브 호환과 부딪치지 않아야 한다.
- **데이터 유출:** 코드나 문서가 외부 서버로 나가는지 확인한다(텔레메트리, 중계 서버, LLM 백엔드).
- **Windows 지원과 무료 범위.**

## 3. 교체 절차
1. **백업:** 설정을 바꾸기 전에 `Logs/EnvRedesign-<날짜>/backup/`에 원본을 복사한다.
2. **시험:** 원본 Unity와 프로젝트 바깥에서 먼저 써 본다(별도 폴더, 격리 worktree, 또는 CLI `--settings` 프로필).
3. **비교:** 기존 도구와 같은 과제로 결과·시간·토큰을 비교한다. 화면 품질은 실제 GameView 캡처로 비교한다.
4. **교체:** 이득이 확인되면 교체하고, 이전 도구는 바로 지우지 말고 꺼 둔다.
5. **기록:** `TOOLING_DESIGN_<날짜>.md`의 표와 `watchlist.json`의 판정을 갱신한다.

**전시 전 동결:** 전시 빌드(월요일) 전에는 캡처·빌드 경로에 닿는 메이저 업그레이드를 하지 않는다. 대상은 Unity 패키지, ffmpeg 메이저, Node 메이저, pillow 메이저다. 패치 버전, 그리고 빌드와 무관한 도구만 갱신한다.

## 5-1. 사용량 실측 (2026-11-09, 공식 session-report 분석 스크립트를 설치 없이 로컬 실행)
- 지난 7일은 **세션 1개**(11-02부터 이어 온 이 세션)에 API 호출 2,938회, 입력 14.9억 토큰(98.9% 캐시 읽기), 출력 288만 토큰이었다.
- 호출당 평균 컨텍스트는 약 **50만 토큰**이다. 대화 하나를 일주일 동안 이어 왔기 때문에, 매 호출마다 50만 토큰을 다시 읽는다.
- 캐시가 깨진 경우(10만 토큰 이상)가 16번 있었고, 매번 약 80만 토큰을 새로 캐시했다. 원인은 세션 도중 `/model` 전환, 데스크탑 이동, 긴 휴식 뒤 재개다.
- 하위 에이전트는 18회에 877만 토큰을 썼다. 오늘 쓴 general-purpose 조사 에이전트는 1회 평균 약 99만 토큰이었다.
- **결론:** 사용량을 가장 크게 좌우하는 것은 플러그인이 아니라 **세션 운영**이다. 다음 순서로 효과가 크다.
  1. 작업 묶음이 끝나면 새 세션을 열고 인계 문서로 이어 간다.
  2. 모델 전환은 세션을 시작할 때만 한다.
  3. 조사는 하위 에이전트 수와 범위를 줄인다.
  4. `CODEX_HANDOFF.md`(10만 자)는 최근 항목만 남기고 나머지는 보관 파일로 옮긴다.

## 6. SNS·영상 레퍼런스 조사를 약관 안에서 하는 방법
- **Instagram:** 사람이 직접 보고 고른 URL만 DevKnowledge(`devk.py`)에 넣는다. 기존처럼 oEmbed와 공개 썸네일만 기록한다. 자동 탐색과 조회수·팔로워 계산은 하지 않는다.
- **YouTube:** 신규 영상 감시는 채널 RSS(`/feeds/videos.xml?channel_id=`)로 한다. 키가 필요 없다. 상세 메타데이터가 필요하면 사용자가 직접 발급한 YouTube Data API v3 키(무료, 하루 10,000 unit)를 사용자 환경변수에 두고 `videos.list`로 받는다. API 데이터 보관 주기 조항은 도입 전에 원문을 확인한다.
- **Reddit:** subreddit RSS(`/r/<sub>/.rss`)로 소량만 수집한다. 공식 API는 앱 승인이 필요하다.
- **광고 레퍼런스:** Meta Ad Library 웹을 사람이 직접 보고 URL과 메모만 남긴다.
- 모든 항목에 출처 URL, 수집 시각, 수집 방식(API/RSS/oEmbed/수동)을 남긴다.
- 미확인: Reddit 약관 원문, Meta Ad Library API 공식 페이지, Handlus 플러그인 라이선스 원문.

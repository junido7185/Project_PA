# Project P.A. Graduation Demo Identity

- 대상: 졸업작품 3~5분 시연
- 기준: `milestone/gameplay-beta-85@29fb98f400b5`
- 상태: 정체성 감사에 따른 데모 설계안. 구현·통합·PPT 수정은 수행하지 않음.

## 1. 데모가 증명해야 할 단 하나

> **Project P.A.는 물건을 직접 모아 파는 게임에서 끝나지 않고, 주민의 생산과 소비 사이를 운영하며 채용과 위임으로 마을 경제를 성장시키는 게임이다.**

관람객은 5분 안에 다음 인과를 이해해야 한다.

```text
주민을 고용한다
→ 그 주민이 생산한다
→ 플레이어가 생산물을 매입한다
→ 가공해 가치를 높인다
→ 가격을 정한다
→ 다른 주민이 성향에 따라 구매/거절한다
→ 매출과 다음 날 마을 변화가 발생한다
→ 다음에는 직접 노동을 더 위임할 수 있다
```

## 2. Demo Identity Sentence 3안

### A. 메커니즘 중심 — 선택

> **생산자를 고용해 원재료를 공급받고, 이를 가공·가격 책정해 주민에게 판매한 결과가 매출과 다음 날 마을 변화로 돌아오는 3~5분 운영 시연.**

장점: 원안의 생산·매입·채용과 현재의 가격·소비·마을 변화를 모두 실제 행동으로 설명한다.

### B. 관람객 중심

> 내가 고용한 주민이 만든 물건을 얼마에 팔지 결정하고, 그 선택으로 주민의 소비와 마을 풍경이 달라지는 코지 경제 시연.

장점: 이해가 빠르고 결과가 선명하다. 단점: 유료 매입과 가공의 부가가치가 약하게 들린다.

### C. 성장 중심

> 직접 재고를 준비하던 개척자가 첫 주민을 고용하고 일을 맡기며 마을 경제의 운영자로 성장하는 첫 5분.

장점: Manual Work→Hiring→Delegation의 성장 판타지가 강하다. 단점: 가격과 NPC 소비가 문장에 직접 드러나지 않는다.

### 선택 이유

**A안**을 최종 Demo Identity Sentence로 선택한다. 교수와 관람객이 “입력 행동→시스템 판단→가시적 결과”를 가장 쉽게 추적할 수 있고, 현재 저장소의 실제 시스템과도 가장 많이 겹친다.

## 3. 현재 상점 중심 데모의 판정

### 현재 데모가 잘 증명하는 것

- 진열대에 실제 상품을 올릴 수 있다.
- 가격을 조정할 수 있다.
- NPC가 가격·성향에 따라 구매 또는 거절한다.
- 돈, 판매 기록, 정산이 갱신된다.
- Day 1 판매 경로는 다수 validator에서 검증되었다.

### 현재 데모만으로는 증명하지 못하는 것

- 왜 프로젝트 이름이 `Pioneer Assistance`인가.
- 상품을 만든 주민은 누구인가.
- 플레이어가 생산물에 왜 돈을 지불하는가.
- 누구를 채용하고 어떤 일을 맡기는가.
- 고용 후 플레이어의 반복 노동이 어떻게 줄어드는가.
- 판매 결과가 주민 생활과 다음 날 마을에 어떻게 환류하는가.
- 작은 상점이 마을 경제의 운영 허브로 어떻게 성장하는가.

### 판정

현재 상점-only 데모는 **기능적으로는 완성도가 높은 핵심 조각**이지만, 정체성 데모로는 부족하다. `상점 운영` 앞의 **NPC 생산·매입**과 뒤의 **채용·위임·마을 변화**가 최소 한 번씩 보여야 Project P.A.로 읽힌다.

## 4. 최소 차별화 조합

기능을 더 많이 보여 주는 것이 목적이 아니다. 아래 다섯 장면이면 충분하다.

1. **유료 채용**: P.A. Phone에서 `마을 농부` 300G 고용.
2. **생산과 매입**: 농부가 만든 Wheat를 돈을 지불하고 인벤토리로 가져옴.
3. **부가가치**: Wheat를 BreadLoaf로 가공하고 원재료와 판매 가치 차이를 표시.
4. **운영 판단**: BreadLoaf의 가격을 정하고 고가 거절→가격 조정→구매를 보여 줌.
5. **경제 환류**: 정산 후 다음 날 Processed 마을 변화와 주민 반응을 보여 줌.

이 조합은 다음 세 축을 동시에 증명한다.

- **Upstream**: 주민 생산·채용·매입
- **Decision**: 가공·상품 구성·가격
- **Downstream**: 주민 소비·매출·마을 변화

## 6. 데모 시작 상태

3~5분 안에 인과를 보장하려면 자유 플레이 시작이 아니라 통제된 데모 상태가 필요하다.

### 필수 시작 조건

- 1920×1080 고정 화면과 안전 영역 확인
- 플레이어가 상점·Phone·농부 작업지·작업대를 10초 내 이동 가능한 위치
- 고용과 1회 매입을 감당할 자금
- `마을 농부`는 미고용 상태
- 생산자 spawn/work/drop-off anchor 유효
- Wheat→BreadLoaf 레시피와 작업대 접근 가능
- 판매대 1개 이상 비어 있음
- 구매/거절을 보여 줄 소비자 경로 준비
- Processed 판매 전 마을 변화 비활성
- 저장 데이터가 아닌 전용 Reset 가능한 데모 상태

### 데모 종료 상태

- 고용 roster 1명 이상
- Wheat 매입 거래 기록
- BreadLoaf 1개 이상 판매
- 구매 또는 거절 이유가 Feed에 남음
- 정산에 매출과 Processed 방향 표시
- 다음 날 Processed 마을 변화 활성
- 마지막 화면에 다음 성장 단계 표시

- 최신 WorldSandbox 전체가 일반 타이틀에서 접근 가능하다.
- 저장/재시작이 완전히 안정적이다.

## 8. 교수에게 20초로 설명하는 구조

> 일반적인 생활 게임은 플레이어가 직접 생산하고 상점 게임은 완성된 상품을 판매합니다. Project P.A.에서는 주민이 생산자이자 소비자입니다. 저는 주민을 고용하고 생산물을 매입해 가공·가격 책정하며, 그 결과가 다시 주민의 소비와 다음 날 마을 변화로 돌아오도록 설계했습니다.

## 11. 최종 Demo Lock 문장

> **졸업 시연은 ‘유료 채용→NPC 생산물 매입→가공→가격 판단→NPC 소비→정산→다음 날 마을 변화’를 한 번 완주해, 직접 생활자가 주민과 시스템을 운영하는 P.A. 관리자로 성장하는 게임임을 증명한다.**

이 흐름과 무관한 기능은 구현량과 관계없이 3~5분 시연의 전면에서 제외한다.

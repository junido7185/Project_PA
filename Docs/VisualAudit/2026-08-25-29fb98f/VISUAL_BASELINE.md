# Project P.A. Visual & Player Experience Baseline

감사일: 2026-08-25\
브랜치/커밋: `milestone/gameplay-beta-85` / `29fb98f400b55dcc7f7e5c580c9b476041d378f4`\
Unity/그래픽스: `6000.3.2f1`, Direct3D 11\
대상: 현재 Build Settings 진입점인 `Assets/Scenes/Prototype_FirstDay.unity`

## 1. 감사 결론

현재 Project P.A.는 **설명자가 옆에서 안내하면 Day 1 판매 데모를 진행할 수 있는 상태**다. 타이틀, 온보딩, 플레이어 스폰, 채집 상태 변화, 진열/가격, 고객 반응, 실제 판매/수익, 휴대폰 감사, 결산, 저장/복원은 한 프로젝트 안에서 실행된다.

하지만 **처음 보는 사용자가 설명 없이 플레이 가능한 졸업작품 빌드**는 아니다.

주된 이유는 다음 세 가지다.

1. 최근 완성도가 높은 생성 월드·낮 활동·제작·7일 루프는 `WorldSandbox` 전용이며 현재 빌드 진입점에서 도달할 수 없다.
2. 현재 화면은 HUD와 팝업의 안전영역, 카메라 가림, 상점 식별, 기능 오브젝트 비주얼이 정리되지 않아 무엇을 해야 하는지 빠르게 읽기 어렵다.
3. M85 통합 저장 재시작은 플레이어 방향 복원 실패로 중단되어 전체 루프 회귀를 끝내지 못했다.

## 2. 감사 방법과 증거 한계

### 실행 전 예상한 정상 플레이 경로

코드와 Build Settings를 기준으로 일반 플레이 경로를 다음처럼 예상했다.

`Prototype_FirstDay` 타이틀 → 새 게임 → 이름/브리핑/맵/휴대폰/조작/보급품 → Day 1 스폰 → 첫 주민 대화 → 판매대 진열 → 가격 설정 → 고객 구매/거절 → P 휴대폰 감사 → F5 저장 → Day 1 결산 → 다음 날 낮 준비 → 저녁 개점 → 고객 → 정산

별도로 M85가 의도한 최신 경로는 다음과 같다.

`WorldSandbox` 시작 → 생성 섬 이동 → 숲/농장/광산/해변 활동 → B05~B08 제작 → B01 판매대 진열/이동 → 밤 개점 → 고객 구매/거절 → Feed/마을 반응 → 7일 진행 → 저장/재시작

후자는 일반 Build Settings에 포함되지 않으므로 실제 제품 진입 경로가 아니다.

### 실제 실행

- Runtime/Editor C# compile: 오류 0.
- D3D11 Core Slice: Play Mode 및 핵심 런타임 구성 PASS.
- D3D11 Gathering + Shop Review: 기능 PASS.
- 비배치 D3D11 Gathering + Shop Review: 캡처 5장 생성, PASS.
- 비배치 D3D11 Final Presentation: 상품 진열/가격/구매/감사/결산 캡처 6장 생성. 마지막 레이아웃 assertion에서 FAIL.
- 비배치 D3D11 감사 전용 캡처: 실제 타이틀 버튼 경로와 격리 저장/복원 PASS, 캡처 5장 생성.
- 사용자 저장은 건드리지 않았고, 감사 저장소만 이 폴더의 `savegame.json`에 사용했다.
- 신규 native crash는 없었다. Editor 종료 시 `JobTempAlloc` 잔여 할당 경고, 관광객 생성 중 AnimatorController 경고 2건은 비차단 런타임 부채로 기록했다.

### 화면비 한계

모든 현재 캡처의 실제 픽셀 크기는 **476×1297**이다. 진단 코드가 1920×1080을 요청했지만 현재 Unity Editor Game View 레이아웃이 세로 패널 크기를 유지했다. 따라서 아래 판정은 이 실행에서 직접 본 화면에 대한 사실이며, 1920×1080 standalone 결과로 일반화하지 않는다. 목표 16:9 화면은 `UNOBSERVABLE`이다.

배치 모드에서는 동일 Game View 캡처가 파일을 쓰지 못하고 timeout 됐다. 같은 방식을 반복하지 않고 비배치 Game View로 증거를 만들었다.

## 3. 처음 플레이하는 사용자가 현재 할 수 있는 것

- 타이틀에서 새 게임, 저장이 있을 때 이어하기, 게임 종료 버튼을 볼 수 있다.
- 새 게임 온보딩의 이름, 브리핑, 맵, 휴대폰, 조작, 보급품 안내를 넘길 수 있다.
- Day 1 월드에서 플레이어를 이동하고 Space로 주민/기능 오브젝트와 상호작용할 수 있다.
- 인벤토리와 핫바를 열고 상품을 판매대에 넣은 뒤 가격을 설정할 수 있다.
- 고객의 구매/거절 반응과 매출 변화를 볼 수 있다.
- 휴대폰 감사 화면에서 누적 매출, Tier 진행, 다음 목표를 볼 수 있다.
- F5/F9 저장/불러오기와 Day 1 결산/다음 날 전환 권위가 연결돼 있다.

다만 이 목록 중 채집 지점까지 자연스럽게 걸어가기, 밤 개점 표지를 발견하기, 고객 이동을 연속 관찰하기, 7일 전체를 일반 입력만으로 완주하기는 이번 자동 실행에서 직접 입증하지 못했다.

## 6. 비주얼 및 사용자 경험 문제

### 시각적 초점

- 타이틀, HUD, 핫바, 스마트폰 상태바, 상호작용 프롬프트가 동시에 보인다.
- 플레이어와 주민의 크기·재질·실루엣이 비슷하고 스폰 지점이 붐벼 주인공을 즉시 찾기 어렵다.
- 상점 허브의 큰 갈색 면과 차양이 카메라 중심을 차지하지만 판매 기능을 설명하지 않는다.

### 비율과 스케일

- 채집 지점의 큐브/막대/조개가 주변 나무 및 캐릭터보다 과장되어 기능 표식처럼 보인다.
- 말풍선은 캐릭터 피드백이 아니라 화면 전체 알림에 가까운 크기다.
- 반대로 타이틀, 조작 안내, 가격 패널, 결산 본문은 현재 화면에서 지나치게 작다.

### 오브젝트 겹침과 이동 동선

- 상점 입구로 보이는 붉은 러그에 플레이어와 NPC가 겹쳐 서 있다.
- 밤/결산 구도는 카메라와 차양 사이의 가림 방지가 작동하지 않는다.
- 판매대가 좌우 테이블처럼 흩어져 있고 내부/외부 경계와 고객 접근 경로를 한눈에 파악하기 어렵다.

### 조명과 색상

- 낮의 따뜻한 저채도 톤은 캐릭터/목재/식생에 비교적 일관된다.
- 20:06 화면에서도 명도와 그림자 색이 낮과 크게 다르지 않아 밤 영업의 감정 전환이 약하다.
- 검정/분홍/크림/녹색 UI가 각 시스템마다 따로 보이며 하나의 제품 UI 체계로 묶이지 않는다.

### UI 가독성

- Final Presentation validator가 `MoneyHUD does not overlap objective panel`에서 실제 실패했다.
- 인벤토리는 화면 밖으로 잘리고 제목, 선택 아이템, 보유량 설명이 보이지 않는다.
- 영어 식별자 `BreadLoaf`, `Tailor_01`, `Plank`가 한국어 플레이 문맥에 섞인다.
- 거대한 반응 말풍선과 작은 정보 패널 사이의 크기 체계가 불균형하다.

### 원시 오브젝트 및 개발 흔적

- 해변 활동 노드는 금지 대상으로 명시된 원시 큐브 조합에 가깝다.
- 화면 상단의 작은 검정 안내, 하단의 `DT 06:00 AM 100%` 폰 상태바, 겹친 프롬프트는 완성 제품보다 진단 표면처럼 보인다.
- Final Presentation 캡처용 카메라 marker/검증 경로가 기능 증거를 만드는 데는 유용하지만, 일반 플레이 화면의 완성도를 대신하지 못한다.

## 7. 기능 연결성과 상태 일관성

### 확인된 연결

- 상품 진열 → 가격 설정 → 구매 → 재고 소비 → 돈 증가 → SalesLog → 감사 누적 매출은 같은 실제 권위를 사용한다.
- Day 준비 채집의 전/후 상태가 같은 지점에서 변한다.
- SaveManager v12는 격리 저장에 핫바/플레이어 상태를 쓰고 같은 세션에서 위치를 복원했다.
- 타이틀 신규 게임은 실제 Day 1 HUD로 진입한다.

### 확인하지 못했거나 끊긴 연결

- `Prototype_FirstDay` 타이틀에서 M85 `WorldSandbox` 전체 루프로 가는 제품 경로가 없다.
- 자동화가 채집·개점·고객 상태를 직접 설정한 구간이 있어 일반 입력만으로의 발견/접근 시간은 측정하지 못했다.
- BETA-010 재시작은 player facing 복원에서 중단돼 full-loop/Golden regression까지 연결되지 않았다.
- 최신 standalone 빌드가 없어 실제 해상도, 앱 종료, 재실행, 이어하기 클릭은 직접 확인하지 못했다.

## 8. 졸업작품 시연 가능성

현재 상태는 다음과 같이 판정한다.

- 설명자가 조작 순서와 판매대 위치를 알려 주는 기능 데모: **가능**
- 처음 보는 사용자가 타이틀부터 Day 1 판매까지 설명 없이 진행: **불안정**
- 생성 월드의 낮 생활 → 제작 → 밤 상점 → 다음 날 변화 → 7일 완주 시연: **현재 빌드에서는 불가**
- 저장 종료 후 재실행을 포함한 완전한 최종 루프: **BETA-010 blocker 때문에 불가**

## 9. 실제 게임 루프를 막는 문제

1. `WorldSandbox` 전체 루프가 빌드 진입점에서 `UNREACHABLE`이다.
2. BETA-010 player facing 복원 실패로 재시작 이후 통합 검증이 멈췄다.
3. 카메라 가림 때문에 밤 상점과 결산의 핵심 장면이 화면에서 사라진다.
4. 상점, 판매대, 채집 노드가 시각적으로 기능을 설명하지 못한다.
5. HUD/팝업의 안전영역과 크기 체계가 없어 첫 사용자가 정보를 우선순위대로 읽기 어렵다.
6. 실제 16:9 standalone 빌드 증거가 없다.

## 10. 사람이 직접 확인해야만 하는 항목

추가 캡처를 이번 Mission에서 요청하지 않는다. 다음 구현 마일스톤의 단일 통합 플레이테스트에서만 확인하면 된다.

- 1920×1080 standalone의 타이틀/HUD/폰/가격/결산 safe area.
- WASD 이동과 카메라 추적, 가림 방지, player/NPC 접지/보행.
- 새 게임에서 채집 지점과 판매대를 도움 없이 찾는 데 걸리는 시간.
- 실제 Space 채집 → 인벤토리 → 제작 → 진열 → 개점 → 고객 구매의 연속 입력.
- F5 저장 → 프로세스 종료 → 재실행 → 이어하기 → 계속 판매.
- Day 1~7 시간 길이, 반복 피로, 사운드, 결과 피드백.

## 11. Goal 설계용 결론

### 다음 Active Mission 후보

1. **BETA-010-PERSISTENCE-RECOVERY-001 — Restore Player Facing and Finish Full Regression**\
   방향 복원 원인을 해결하고 restart/repeated-load, BETA-007/008, Golden/M70 회귀까지 끝낸다.

3. **TARGET-ASPECT-AND-CAMERA-GATE-001 — 16:9 UI Safe Area and Occlusion**\
   목표 1920×1080 Game View/빌드 기준을 고정하고, 상점 차양 가림·HUD 겹침·팝업 스케일을 먼저 해결한다.
4. **SHOP-READABILITY-ONBOARDING-001 — Identify the Shop and Sales Flow**\
   상점 입구/내부/판매대/개점 간판/첫 동선을 실제 카메라에서 읽히게 만든다.

   해변/숲/광산/농장의 원시 큐브와 거대 라벨을 기존 아트 방향에 맞는 기능 에셋과 피드백으로 교체한다.
6. **PLAYABLE-BUILD-GATE-001 — Produce and Audit a Standalone Candidate**\
   빌드 생성, 새 프로필, 저장 종료/재실행, 16:9 캡처, 처음부터 끝까지 완주 증거를 한 번에 묶는다.

### 플레이 가능한 졸업작품에 반드시 필요한 것

- 하나의 타이틀과 하나의 도달 가능한 최종 게임 루프.
- 낮 활동 → 인벤토리 → 제작 → 진열 → 밤 영업 → 고객/수익 → 다음 날 변화의 연속 입력.

- 상점/판매대/활동 지점의 즉시 식별 가능성.
- 16:9 카메라 가림 방지와 UI safe area.
- 최소 한 주 또는 명확한 엔딩/마일스톤까지의 실제 플레이 시간과 결과 화면.

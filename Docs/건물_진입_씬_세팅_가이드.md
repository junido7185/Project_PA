# 씬 세팅 완전 가이드 — Build UI System → 건물 진입까지

> **작성:** 세션 17 (2026-04-16)  
> **대상:** 씬이 거의 빈 상태 or 서비스/UI 미배치 상태에서 시작  
> **목표:** 이 문서만 따라하면 플레이어가 건물 안을 오갈 수 있는 상태까지 완성

---

## 진행 순서 한눈에 보기

```
PHASE 1 — 컴파일 에러 없는지 확인          (1분)
PHASE 2 — Services 배치                   (10분)
PHASE 3 — Player 오브젝트 확인             (5분)
PHASE 4 — Build UI System 실행            (2분)
PHASE 5 — ScreenFader 배치               (2분)
PHASE 6 — 건물 진입 씬 세팅               (15분)
PHASE 7 — 테스트 & 문제 해결              (5분)
```

## PHASE 1 — 컴파일 에러 확인

> Unity가 스크립트를 컴파일 못 하면 아무것도 안 된다. 제일 먼저 확인.

1. Unity 에디터 하단 **Console 탭** 열기
2. 빨간 에러(❌)가 없는지 확인
3. 에러가 있으면 해결 후 진행. **경고(⚠️)는 무시해도 됨**

---

## PHASE 2 — Services 배치

> 싱글톤 서비스들. 씬 내에 딱 하나씩만 존재해야 한다.  
> **실행 순서가 정해져 있으므로 아래 순서대로 만들 것.**

### 2-0. Services 그룹 만들기

1. Hierarchy 빈 곳 우클릭 → **Create Empty**
2. 이름: `[Services]`
3. Position: `(0, 0, 0)` 고정 (이동할 일 없음)

---

### 2-1. EconomyService (ExecutionOrder -100)

1. `[Services]` 우클릭 → **Create Empty** → 이름: `EconomyService`
2. Add Component → **`Economy Service`** 검색 추가
3. Inspector 설정:
   - `_money` (Money 시작값): `1000` 추천 (테스트용)

---

### 2-2. TierService (ExecutionOrder -90)

1. `[Services]` 자식에 빈 GO → 이름: `TierService`
2. Add Component → **`Tier Service`** 추가
3. **TierDefinition ScriptableObject 5개 생성 필수**

   **에셋 생성 방법:**
   - Project 패널에서 `Assets/Data/` 폴더 (없으면 생성)
   - 우클릭 → **Create → P.A. → TierDefinition** (또는 ScriptableObject 커스텀 메뉴)
   - 만약 메뉴가 없으면: 우클릭 → Create → ScriptableObject → 검색창에 `TierDefinition`
   - 파일 5개 생성: `Tier0.asset` ~ `Tier4.asset`

   **각 에셋 설정 (Inspector):**

   | 에셋 | tierLevel | tierName | revenueRequired | shopSlotCount | shopStageName |
   |---|---|---|---|---|---|
   | Tier0 | 0 | 생존자 | 0 | 4 | 가판대 |
   | Tier1 | 1 | 지점장 | 5000 | 8 | 잡화점 |
   | Tier2 | 2 | 관리자 | 20000 | 16 | 마트 |
   | Tier3 | 3 | 사업가 | 60000 | 32 | 백화점 |
   | Tier4 | 4 | 파트너 | 150000 | 32 | 플래그십 |

   **TierService Inspector에 등록:**
   - `Tier Definitions` 리스트 크기 = **5**
   - Element 0 = Tier0.asset, Element 1 = Tier1.asset ... 순서대로 드래그

---

### 2-3. GameClock (ExecutionOrder -80)

1. `[Services]` 자식에 빈 GO → 이름: `GameClock`
2. Add Component → **`Game Clock`** 추가
3. Inspector 설정:
   - `Seconds Per Game Hour`: `10` (테스트 중엔 빠르게, 완성 후 60으로)
   - `Start Hour`: `7` (오전 7시 시작)
   - `Days Per Season`: `7`

---

### 2-4. ItemRegistry (ExecutionOrder -70)

1. `[Services]` 자식에 빈 GO → 이름: `ItemRegistry`
2. Add Component → **`Item Registry`** 추가
3. `All Items` 리스트에 **만들어둔 모든 Item ScriptableObject 등록**
   - Item 에셋이 없으면 일단 비워두고 진행 가능 (나중에 채움)
   - ⚠️ Item을 등록하지 않으면 저장/로드 시 아이템 데이터를 못 찾음

---

### 2-5. HiringService (ExecutionOrder -60)

1. `[Services]` 자식에 빈 GO → 이름: `HiringService`
2. Add Component → **`Hiring Service`** 추가
3. `Available Candidates` / `Spawn Point` — 나중에 NPC 만들 때 설정, **지금은 비워도 됨**

---

### 2-6. FriendshipService (ExecutionOrder -60)

1. `[Services]` 자식에 빈 GO → 이름: `FriendshipService`
2. Add Component → **`Friendship Service`** 추가
3. `Hidden Blueprints` — 나중에 설정, **지금은 비워도 됨**

---

### 2-7. GridService (ExecutionOrder -50)

1. `[Services]` 자식에 빈 GO → 이름: `GridService`
2. Add Component → **`Grid Service`** 추가
3. Inspector:
   - `Cell Size`: **`2.0`** (BuildManager.gridSize 와 반드시 일치)

---

### 2-8. AuditService (ExecutionOrder -40)

1. `[Services]` 자식에 빈 GO → 이름: `AuditService`
2. Add Component → **`Audit Service`** 추가
3. `Audit Interval Days`: `7` (7일마다 자동 평가)
4. 나머지 임계값 필드들은 기본값 유지

---

### 2-9. BuildingRegistry

1. `[Services]` 자식에 빈 GO → 이름: `BuildingRegistry`
2. Add Component → **`Building Registry`** 추가
3. 설정 필드 없음, 추가만 하면 됨

---

### 2-10. SaveManager

1. `[Services]` 자식에 빈 GO → 이름: `SaveManager`
2. Add Component → **`Save Manager`** 추가
3. `All Building Types` 리스트 — 나중에 BuildingData 에셋 만들면 등록

## PHASE 3 — Player 오브젝트 확인

> 이미 있는 Player GameObject에 컴포넌트가 제대로 붙어있는지 체크.

### 3-1. Player 컴포넌트 체크리스트

Player GameObject 선택 후 Inspector에서 아래 컴포넌트들이 있는지 확인:

```
[ ] CharacterController    ← 이동 물리 (없으면 Add Component)
[ ] PlayerController       ← 이동 로직
[ ] PlayerInteraction      ← Space 키 상호작용
[ ] PlayerInputHandler     ← 키 입력 중앙 관리
[ ] Inventory              ← 인벤토리 데이터
[ ] Hotbar                 ← 핫바 데이터
[ ] BuildManager           ← 건설 기능 (없어도 테스트 가능)
```

### 3-2. Inventory Inspector 설정

- `Slots` 리스트 크기: **20** (InventorySlot 20개 자동 생성됨)
- `Hotbar` 필드: 아래 Hotbar 컴포넌트를 드래그 연결

### 3-3. PlayerInteraction Inspector 설정

- `Interact Distance`: **`2.0`**
- `Interact Layer`: 지금은 비워도 됨 (SphereCast가 레이어 필터 없이 작동)
- `Farmland Prefab`: Farmland 프리팹 있으면 연결, 없으면 비워도 됨

## PHASE 4 — Build UI System 실행

> PA_UIBuilder가 Canvas, 인벤토리 패널, 핫바, 스마트폰 UI를 모두 자동 생성한다.

### 4-1. 실행

1. Unity 상단 메뉴 → **`P.A. System`** → **`Build UI System`** 클릭
2. 확인 다이얼로그 → **"빌드 시작"** 클릭
3. 프로그레스 바가 돌다가 "완료" 다이얼로그 → **"확인"**

### 4-2. 생성된 항목 확인

Hierarchy에 자동으로 생긴 것들:
```
PA_UIRoot (Canvas)
  ├─ DragLayer
  ├─ Tooltip
  ├─ HotbarRoot
  │    └─ 핫바 슬롯 9개
  ├─ InventoryPanel      ← I 키로 토글
  │    └─ 인벤토리 슬롯들
  └─ SmartphoneContainer ← P 키로 팝업
       └─ 폰 UI 계층
EventSystem
```

### 4-3. 자동 연결 확인

PA_UIBuilder가 씬에서 `Inventory`, `Hotbar`, `Player` 를 찾아서 UI 컴포넌트에 참조를 자동 연결한다.

**확인 방법:**
- `PA_UIRoot > HotbarRoot` 의 `HotbarUI` 컴포넌트 → `hotbar` 필드 비어있지 않은지
- `PA_UIRoot > InventoryPanel` 의 `InventoryUI` 컴포넌트 → `inventory` 필드 연결됐는지

만약 비어있으면:
- Player GameObject에 Inventory/Hotbar 컴포넌트가 없는 것 → PHASE 3 재확인

### 4-4. ⚠️ 주의사항

- **Build UI System은 기존 PA_UIRoot를 삭제하고 재생성함**
- 수동으로 PA_UIRoot 안에 뭔가 추가했다면 지워짐
- 씬이 저장된 상태에서 실행할 것 (Ctrl+S 먼저)

## PHASE 6 — 건물 진입 씬 세팅

> 이제 실제로 건물 안으로 들어갈 수 있도록 만든다.  
> 패턴: **외부 문** ↔ **실내 영역(Y+100)** ↔ **내부 문**

### 6-1. 실내 루트 GameObject 만들기

1. Hierarchy 최상단(아무 오브젝트 아래도 아님)에 빈 GO 생성
2. 이름: `Interior_Shop`
3. Transform Position: **`X=0, Y=100, Z=0`** ← Y=100이 핵심

### 6-2. 실내 바닥 만들기

1. `Interior_Shop` 우클릭 → Create Empty → 이름: `Floor`
   - 또는 3D Object → Plane
2. Plane을 쓴 경우 Position: `(0, 100, 0)`, Scale: `(0.8, 1, 0.8)`
   - Plane 기본 크기가 10×10이라 Scale 0.8이면 8×8m 정도
3. (선택) Material로 바닥 색상 구분

### 6-3. 실내 간이 조명

1. `Interior_Shop` 자식에 **Light → Point Light** 생성
2. Position: `(0, 103, 0)` (바닥 3m 위)
3. Intensity: `2`, Range: `10`

### 6-4. 실내 진입 스폰 포인트

> 플레이어가 외부에서 진입했을 때 도착할 위치

1. `Interior_Shop` 자식에 빈 GO 생성
2. 이름: `PlayerSpawn_Inside`
3. Position: `(0, 100.1, 0.5)` ← 바닥보다 0.1 위, 실내 중앙 약간 앞
4. **Rotation Y**: 실내 안쪽을 바라보는 방향으로 설정
   - Scene 뷰에서 파란 화살표(Z축)가 실내 안쪽을 향하도록

### 6-5. 외부 복귀 스폰 포인트

> 실내에서 나왔을 때 외부에 서는 위치

1. Hierarchy 최상단(Interior_Shop 밖)에 빈 GO 생성
2. 이름: `PlayerSpawn_Outside_Shop`
3. Position: 건물 외부 문 앞 약 `1.5m` (예: `(0, 0.1, -3)`)
4. **Rotation Y**: 건물에서 등을 돌리는 방향 (밖을 바라봄)

### 6-6. 외부 문 만들기

> 플레이어가 밖에서 Space를 눌러 실내로 진입하는 문

1. Hierarchy 최상단에 빈 GO 생성
2. 이름: `Door_Out_Shop`
3. Position: 건물 입구 앞 (예: `(0, 1, -2)`) — 기존 건물 모델이 있으면 문 앞에 배치

4. **Box Collider 추가**
   - Add Component → `Box Collider`
   - Is Trigger: **체크 해제** (반드시 꺼야 SphereCast 히트)
   - Size: `(1.5, 2.2, 0.3)` (문 폭 1.5m, 높이 2.2m, 두께 0.3m)
   - 초록 박스가 문 위치를 덮는지 Scene 뷰에서 확인

5. **BuildingEntrance 추가**
   - Add Component → `Building Entrance`
   - `Target Spawn`: `PlayerSpawn_Inside` 드래그 연결
   - `Prompt Label`: `"상점 입장"`

### 6-7. 내부 문 만들기

> 실내에서 Space를 눌러 밖으로 나가는 문

1. `Interior_Shop` 자식에 빈 GO 생성
2. 이름: `Door_In_Shop`
3. Position: `(0, 100.5, -0.5)` ← 실내 입구 반대편 (PlayerSpawn_Inside 뒤쪽)

4. **Box Collider 추가**
   - Is Trigger: **체크 해제**
   - Size: `(1.5, 2.2, 0.3)`

5. **BuildingEntrance 추가**
   - `Target Spawn`: `PlayerSpawn_Outside_Shop` 드래그 연결
   - `Prompt Label`: `"나가기"`

### 6-8. ✅ 최종 Hierarchy 구조

```

  ├─ EconomyService
  ├─ TierService

  ├─ HiringService

  └─ ScreenFader
```

## PHASE 7 — 테스트

### 7-1. Play 모드 진입 전 저장

- **Ctrl+S** (씬 저장)
- Build UI System 실행 후 씬 변경 사항이 있으므로 반드시 저장

### 7-2. Play 버튼

Console 탭을 열어두고 Play 시작.

**정상 로그 (처음 몇 초):**
```
💰 EconomyService[init]: ... → 1000G
⏰ GameClock: 1일 07:00
```

**문 앞 접근 → Space 키:**
```
🚪 워프: Player → PlayerSpawn_Inside
```

### 7-3. 테스트 체크리스트

```
[ ] Play 진입 시 Console 빨간 에러 없음
[ ] WASD로 플레이어 이동 됨
[ ] Door_Out_Shop 앞 2m 이내에서 Space → 화면 페이드 후 실내 이동
[ ] 실내 바닥 위에 서 있음 (공중이나 바닥 아래 아님)
[ ] 카메라가 즉시 실내를 비춤 (느린 패닝 없음)
[ ] Door_In_Shop 앞에서 Space → 외부로 복귀
[ ] I 키 → 인벤토리 패널 토글
[ ] P 키 → 스마트폰 팝업
```

## 자주 나오는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| Space 눌러도 무반응 | Door Collider 없거나 Is Trigger=on | BoxCollider 확인, Is Trigger 해제 |
| 화면 안 까매짐 | ScreenFader 없음 | [Services] > ScreenFader + 컴포넌트 확인 |
| 워프 후 플레이어 안 보임 | 실내 조명 없음 | Interior_Shop에 PointLight 추가 |
| 플레이어가 바닥 아래로 떨어짐 | PlayerSpawn_Inside Y가 너무 낮음 | Y를 +0.5 씩 올려서 테스트 |
| 카메라가 느리게 따라옴 | CameraController가 Camera에 없음 | Main Camera → CameraController 컴포넌트 + target=Player 연결 |
| TierService 에러 | TierDefinition 에셋 미등록 | PHASE 2-2 재확인 |
| InventoryUI 참조 에러 | Build UI System 미실행 or Player에 Inventory 없음 | PHASE 3→4 재확인 |
| Space가 점프로 작동 | Input System 충돌 | PlayerInputHandler가 씬에 하나인지 확인 |

## 여러 건물 추가 (패턴 복사)

건물 하나 추가할 때마다 이것만 반복:

```
새 Interior_{이름}  → Y=200, Y=300 ... (건물마다 100씩 올림)
  PlayerSpawn_Inside_{이름}
  Door_In_{이름}     (targetSpawn = PlayerSpawn_Outside_{이름})

Door_Out_{이름}     (targetSpawn = PlayerSpawn_Inside_{이름})
PlayerSpawn_Outside_{이름}
```

**BuildingEntrance 컴포넌트만 붙이면 되므로 건물당 5분.**

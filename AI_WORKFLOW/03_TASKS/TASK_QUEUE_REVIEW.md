## 발견·보완 내역

1. **Task 041 선행작업 오타** → "Task 039, Task 010"으로 수정(완료).
2. **YES 작업 선택 규칙 부재** → TASK_QUEUE Review Notes + REPEAT 프롬프트에 "미승인 YES는 스킵하고 다음 NO 작업" 규칙 추가(완료).
3. **첫 실행 연결** → Review Notes에 "첫날은 Task 001~003, `CODEX_FIRST_RUN_PLAYBOOK` 준수" 추가(완료).

## 남은 주의점 (작업 추가 없이 문서로 관리)

- **Phase 5 마을 변화의 "가시성"**: 트렌드 점수가 로그로만 남고 화면 변화로 이어지지 않으면 핵심 차별점이 죽는다. Task 049/053의 완료 조건에 이미 "플레이어 화면에서 읽히는지"가 있으나, 검수 시 VERIFICATION §E(마을 변화 최소 증거)를 반드시 적용할 것.
- **낮 활동과 밤 영업 분리 위험**: Task 041/045/068이 연결 검증을 담당. 이 세 작업을 건너뛰면 루프가 조각날 수 있으므로 우선순위 유지.
- **L 작업 분할 여지**: 068(1일 루프 통합), 076/077(가게·시설 확장)은 착수 전 `CODEX_TASK_SPLIT_PROMPT` 사용을 권장.

## 종합 판정

TASK_QUEUE는 **Codex 투입 가능**하다. 순서(안정화→루프→저장→데모→확장), 사람 승인 게이트, 위험 파일 보호, 낚시 중심 차별점 표현이 모두 갖춰졌다. 작업을 추가하지 않고 오타 1건 수정 + Review Notes로 검수를 마쳤다(요구된 "번호 갈아엎기 금지, 보완 우선" 원칙 준수).

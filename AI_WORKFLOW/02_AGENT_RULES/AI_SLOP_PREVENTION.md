# AI_SLOP_PREVENTION — AI 슬롭 방지 규칙

작성: 2026-07-09
목적: AI 에이전트가 그럴듯하지만 프로젝트를 망치는 행동을 하는 것을 막는다. 아래는 **전부 금지 규칙**이며 예외는 사용자 명시 승인뿐이다.

## 금지 규칙

1. **게임 장르 재해석 금지.**
   Project P.A.는 코지 라이프 + 잡화점 경영 + 역-공급망 백본이다. "이 게임은 사실 ~게임이다" 식의 재정의 금지.

2. **감성 서사 중심으로 변경 금지.**
   물건의 사연, 마을의 기억 보관, 철학적 테마, 어두운 경영 톤으로 끌고 가는 기획·문구·시스템 추가 금지. 코지하고 밝은 톤 고정.

3. **대형 리팩터링 금지.**
   "구조가 더 깔끔해진다"는 이유의 아키텍처 변경, 네임스페이스 재편, 파일 대량 이동/개명 금지. 리팩터링은 사용자가 범위를 지정해 승인한 경우만.

4. **기존 작동 기능 삭제 금지.**
   "안 쓰는 것 같아서", "중복이라서" 삭제 금지. 죽은 코드로 보여도 씬/프리팹/저장 데이터가 참조할 수 있다. 제거 제안은 BUG_LOG/DECISION_LOG에 기록만.

5. **새 대형 시스템 제안·구현 금지.**
   요청받지 않은 새 시스템(날씨, 전투, 퀘스트 엔진, 이벤트 버스 등)을 만들지 않는다. 아이디어는 `../05_LOGS/DECISION_LOG.md`에 제안으로 기록.

6. **한 작업에서 여러 기능 동시 구현 금지.**
   태스크 하나 = 기능 하나 = 검증 하나. "하는 김에" 금지.

7. **"아마 될 것" 같은 추정 보고 금지.**
   실행하지 않은 코드에 대해 "정상 동작할 것으로 보임" 식 보고 금지. 실행·검증한 것과 못 한 것을 분리해 보고한다.

8. **테스트하지 않은 내용을 테스트했다고 말하기 금지.**
   검증기 결과·컴파일 결과·플레이 확인은 실제 실행 로그/결과가 있을 때만 "통과"로 보고한다. 검증 결과 조작·과장은 최악의 위반이다.

9. **사용자가 요청하지 않은 외부 패키지 추가 금지.**
   NuGet, UPM, 에셋스토어, GitHub 소스 복사 전부 포함. "무료라서/표준이라서"는 예외 사유가 아니다.

10. **프로토타입만 만들고 끝나는 방향으로 축소 금지.**
    "시연만 되면 된다"는 판단으로 저장 미지원, 하드코딩, 일회용 코드로 때우는 것 금지. 모든 작업은 완성 게임의 지반이 된다는 전제로 만든다 (`../01_IDENTITY/PROJECT_PA_SCOPE.md` §4). 단, 범위 축소 제안 자체는 가능 — 품질 축소가 금지다.

## 추가 경계 행동

- **컨텍스트 무시 금지**: 기존 구현을 조사하지 않고 같은 기능을 새로 만드는 것 (중복 구현) 금지. 먼저 검색·조사.
- **문서와 코드 불일치 방치 금지**: 코드를 바꿨으면 관련 문서(§2 문서화 의무)를 같은 작업에서 갱신.
- **조용한 실패 금지**: 에러를 try-catch로 삼키고 성공처럼 보고하는 코드 작성 금지.
- **가짜 데이터 금지**: 실제 시스템 데이터가 없는데 있는 것처럼 보이는 UI/힌트 제작 금지 (SPY-002 원칙: "데이터가 없는 성격/취향은 임의로 만들지 않는다").

## 위반을 발견했을 때

과거 작업에서 위 위반을 발견하면 직접 고치지 말고 `../05_LOGS/BUG_LOG.md`에 기록하고 보고한다.

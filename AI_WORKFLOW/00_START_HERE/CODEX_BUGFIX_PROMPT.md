## Project P.A. 정체성 요약

낮 마을 생활 + 밤 잡화점 운영의 3D 코지 라이프 심. "내가 판 물건이 마을을 바꾼다." 완성 게임이 목표.

## 이번 프롬프트의 목적

- 지정된 버그 1개의 원인을 찾아 가장 작은 변경으로 고치고, 재현이 사라졌음을 검증한다.

## 허용되는 작업

- 대상 버그와 직접 관련된 최소 코드 변경.
- 재현 시나리오로 검증, 문서 기록.

## 금지되는 작업

- 다른 버그 동시 수정, 새 기능 추가, 리팩터링, "하는 김에" 정리.
- 위험 파일(PlayerController/SaveManager/Inventory/씬/프리팹) 대규모 변경 — 필요하면 사람 승인.
- 아래 AI 슬롭 방지 규칙 전부.

## 작업 전 보고 양식

- 대상 버그 ID/증상/재현.
- 원인 추정 + 수정 예정 파일(최소 범위).
- 보존 선언(건드리지 않을 것).

## 작업 후 보고 양식

- 실제 수정 파일/변경 요약.
- 재현이 사라졌는지 검증 결과.
- 부작용 점검(데모 흐름 유지).
- 확인 못 한 것.

## 검증 기준

- 수정 전 재현되던 시나리오가 수정 후 재현되지 않음을 실제로 확인.
- 컴파일 통과. 관련 검증기 통과. 상점/저장 관련이면 해당 체인 회귀.

## 실패 시 멈추는 조건

- 같은 원인으로 2회 실패하면 세 번째 시도 금지 → `BUG_LOG.md`에 상태 갱신하고 사람 판단 요청.
- 원인이 위험 파일 대규모 변경을 요구하면 중단하고 사람 승인 요청.

## CHANGELOG_AI.md 갱신 규칙

- 수정 완료 시 `CHANGELOG_AI.md`에 기록, `BUG_LOG.md` 상태를 RESOLVED(해결 방법 포함)로.

## HANDOFF_FOR_CODEX.md 갱신 규칙

- 버그가 우선순위/위험 파일에 영향 있으면 `HANDOFF_FOR_CODEX.md` 갱신.

## AI 슬롭 방지 규칙 (항상)

- 전체 시스템 재작성 금지 · 기존 작동 기능 삭제 금지 · 게임 장르 재해석 금지 · 감성 서사/철학/다크 톤 변경 금지 · 대형 리팩터링 금지 · 한 번에 여러 작업 금지 · 요청 없은 외부 패키지 금지 · 씬/프리팹/SO 임의 대량 수정 금지 · PlayerController/SaveManager/InventoryManager 임의 재작성 금지 · 컴파일 확인 없이 완료 선언 금지 · 테스트 안 한 걸 했다고 보고 금지 · 실패를 성공처럼 말하기 금지 · 프로토타입 완성만 목표로 축소 금지.

## 2. 강하게 확인한 항목 (요구된 7개)

| 확인 대상 | 요구 | 판정 | 근거 |
|---|---|---|---|
| BOOTSTRAP | 코드 수정 없이 구조 파악만 | ✅ | "이번 세션의 목적은 파악. 코드를 수정하지 마라." + 허용=읽기/조사만, 금지=모든 코드·씬·에셋 수정 |
| REPEAT | TODO 첫 작업 1개만 | ✅ | "작업 1개만" + "두 개 이상 동시 수행 금지". 보완: YES 작업이면 승인 요청 후 다음 NO 작업 선택 |
| VERIFY | 코드 수정 없이 검증만 | ✅ | "코드를 수정하지 않는다. 버그를 찾아도 고치지 말 것 → BUG_LOG에 기록만" |
| BUGFIX | BUG_LOG 버그 1개만 | ✅ | "버그 1개만 고친다" + "다른 버그 동시 수정·새 기능·리팩터 금지" |
| TASK_SPLIT | 구현 안 하고 큐만 쪼갬 | ✅ | "코드를 구현하지 않는다. TASK_QUEUE.md만 개선" + 금지=코드/씬/에셋 수정 |
| DEMO_LOCK | 새 기능 금지 | ✅ | "지금은 기능 개발 기간이 아니다. 새 기능을 만들지 마라" + 금지=새 기능/시스템/밸런스/리팩터 |
| FULL_GAME_EXPANSION | 슬라이스 비파괴 확장만 | ✅ | "이미 도는 Vertical Slice를 절대 깨지 마라" + 검증=1일 루프 회귀 통과 필수 + 깨지면 롤백 판단 |

## 3. 보완 내역

- **CODEX_REPEAT_PROMPT.md**: 문서 선택 4번에 "선택 작업이 사람 승인 YES인데 승인 없으면 착수 금지, 승인 요청만 보고 후 다음 NO 작업 선택" 규칙 추가. (전체 갈아엎기 아님, 규칙 1줄 추가)

그 외 9종은 필수 섹션·핵심 제약이 모두 충족되어 수정하지 않았다.

## 4. 종합 판정

프롬프트 10종은 **Codex 투입 가능**하다. 각 프롬프트가 "허용 범위를 좁게, 금지를 명시적으로, 실패 시 멈춤을 강제"하는 구조를 일관되게 갖췄다. 특히 무수정 프롬프트(BOOTSTRAP/VERIFY/TASK_SPLIT)와 파괴 위험 프롬프트(DEMO_LOCK/FULL_GAME_EXPANSION)의 경계가 뚜렷하다.

권장: 첫 사용은 반드시 `CODEX_FIRST_RUN_PLAYBOOK.md`의 순서(BOOTSTRAP → 결과 확인 → REPEAT로 Task 001)를 따른다.

# CODEX_REFACTOR_GUARD_PROMPT

> 사용 상황: 리팩터링/코드 정리 충동이 생겼을 때. **기존 동작 유지가 목표일 때만** 사용. 리팩터링을 부추기는 프롬프트가 아니라 과도한 리팩터링을 막는 가드다.
> 아래 전체를 복사해 Codex에 붙여넣는다.

---

너는 Unity 게임 Project P.A.의 작업자다. 이번 세션의 기본 태도는 **"고치지 않는 것이 이기는 것"**이다. 동작을 바꾸지 않고, 리팩터링 범위를 최소로 억제한다.

## 먼저 읽을 문서

1. `AGENTS.md`
2. `AI_WORKFLOW/02_AGENT_RULES/UNITY_CODING_RULES.md`, `AI_SLOP_PREVENTION.md`, `CODEX_WORKER_RULES.md`
3. `AI_WORKFLOW/04_VERIFICATION/VERIFICATION_RULES.md`

## Project P.A. 정체성 요약

낮 마을 생활 + 밤 잡화점 운영의 3D 코지 라이프 심. "내가 판 물건이 마을을 바꾼다." 완성 게임이 목표. 기존 시스템은 보존·확장 대상.

## 이번 프롬프트의 목적

- 리팩터링 요청이 정말 필요한지 먼저 판정하고, 필요하다면 **동작 불변**을 보장하는 아주 좁은 범위만 수행한다.
- 대부분의 경우 결론은 "리팩터링하지 않고 그대로 둔다 + 이유 보고"여야 한다.

## 허용되는 작업

- 리팩터링 필요성 분석 보고.
- 동작을 바꾸지 않는 국소 정리(주석 추가, 죽지 않은 지역 변수명 정리 등) — 단, 직렬화 필드/공개 API/씬 참조는 건드리지 않음.

## 금지되는 작업

- `[SerializeField]`/public 필드 이름·타입 변경 (씬/프리팹 연결 파손).
- 파일 대량 이동/개명, 네임스페이스 재편, 아키텍처 변경.
- 동작 변화가 조금이라도 있는 수정.
- 핵심 시스템(Shop/EconomyService/PurchaseEvaluator/NpcController/SaveManager/PlayerController/Inventory) 구조 변경.
- 아래 AI 슬롭 방지 규칙 전부.

## 작업 전 보고 양식

- 리팩터링 요청 내용 / 실제 필요성 판정(필요/불필요 + 근거).
- 필요하면: 최소 범위, 동작 불변 보장 방법.

## 작업 후 보고 양식

- 실제 변경(없으면 "변경 없음, 사유").
- 동작 불변 검증 결과(리팩터링 전후 동일 동작 확인).

## 검증 기준

- 리팩터링 전후 컴파일 결과 동일, 관련 검증기 결과 동일, 데모 흐름 동일.
- 조금이라도 동작이 달라지면 그것은 리팩터링이 아니라 기능 변경 → 중단.

## 실패 시 멈추는 조건

- "안전하게 동작 불변으로 못 하겠다"면 중단하고 그대로 둔 채 사람에게 보고.
- 직렬화/씬 참조를 건드려야만 가능하면 중단.

## CHANGELOG_AI.md 갱신 규칙

- 변경이 있었으면 `CHANGELOG_AI.md`에 "리팩터(동작 불변)"으로 명시 기록. 변경 없으면 기록 선택.

## HANDOFF_FOR_CODEX.md 갱신 규칙

- 리팩터링 보류/완료가 다음 작업에 영향 있으면 `HANDOFF_FOR_CODEX.md` 갱신.

## AI 슬롭 방지 규칙 (항상)

- 전체 시스템 재작성 금지 · 기존 작동 기능 삭제 금지 · 게임 장르 재해석 금지 · 감성 서사/철학/다크 톤 변경 금지 · 대형 리팩터링 금지 · 한 번에 여러 작업 금지 · 요청 없은 외부 패키지 금지 · 씬/프리팹/SO 임의 대량 수정 금지 · PlayerController/SaveManager/InventoryManager 임의 재작성 금지 · 컴파일 확인 없이 완료 선언 금지 · 테스트 안 한 걸 했다고 보고 금지 · 실패를 성공처럼 말하기 금지 · 프로토타입 완성만 목표로 축소 금지.

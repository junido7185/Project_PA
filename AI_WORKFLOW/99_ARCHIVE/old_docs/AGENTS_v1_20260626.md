# Project PA Agent Guide

Project PA is the only writable target for agent work:

`C:\Users\sdjsd\Desktop\Unity\Project_PA`

Reference prototype:

`C:\Users\sdjsd\Desktop\Unity\Project_D\Project_D`

The reference project is read-only and only for visual/staging ideas. Do not copy, merge, rename after, or modify it.

## Identity

Read `PROJECT_PA_CREATIVE_NORTH_STAR.md` before gameplay, UI, art, economy, NPC, or scene work.

Project PA is a cozy 3D life and shop management simulation:

- Day: explore, gather, talk, prepare, process, and plan.
- Night: open the shop, display goods, set prices, watch customers, settle the day.
- Long term: sold product categories and NPC support change the village economy and culture.

Do not reduce it to a simple shop clone or a reference-project remake.

## Required Preflight

Before changing anything:

- Confirm current path is Project_PA.
- Confirm Git root is Project_PA.
- Check `git status`.
- Confirm `Assets/`, `Packages/`, and `ProjectSettings/` exist.
- Check whether Unity Editor is already open.
- Check recent crash reports if validation or Unity launch is involved.

If the root is wrong, stop.

## Context Rules

Use `Docs/AgentWorkflow/CONTEXT_INDEX.md` to choose the minimum required documents for the task.

For gameplay-related work, always include:

- `PROJECT_PA_CREATIVE_NORTH_STAR.md`
- `PROJECT_PA_DESIGN_INTENT.md`
- current milestone/status/TODO/session report

Do not read every document by default when a smaller context set is enough.

## Forbidden Work

- Do not modify Project_D.
- Do not copy Project_D assets, scripts, scenes, materials, or project settings.
- Do not import external packages without explicit approval.
- Do not run destructive commands.
- Do not use `git reset --hard`, `git clean -fd`, or `rm -rf`.
- Do not push to GitHub.
- Do not auto-commit unless the user explicitly asks.
- Do not create infinite loops, scheduled tasks, or self-invoking agent loops.
- Do not delete local project files.
- Do not rewrite core shop/economy/NPC/save systems broadly.

## Safe Development Order

1. Read the relevant context from `CONTEXT_INDEX.md`.
2. Inspect existing code/scenes before editing.
3. Make the smallest useful change.
4. Run compile checks or validators when safe.
5. If Unity is open, do not start batchmode validators for the same project.
6. Update status/TODO/session docs.
7. Record validation evidence and remaining human checks.

## Validation Rules

Prefer existing validators in `Automation/LoopEngineering/validator-registry.json`.

Use Unity batchmode only when the project is not already open in another Unity Editor instance.

If compile or validator failures repeat, stop and document the blocker instead of forcing more changes.

Human review is required for:

- subjective visual quality
- Game view readability
- scene layout approval
- save schema changes
- new gameplay systems
- balance changes

## Git Rules

- Inspect `git status` before and after.
- Do not revert user changes.
- Do not commit unless explicitly requested.
- Do not push.

# DEVELOPMENT_TIMELINE — TASK_QUEUE 기반 개발 일정 추정

작성: 2026-07-09
성격: **희망 일정이 아니라 추정표.** `TASK_QUEUE.md`(85개 작업)의 난이도 분포·검증 시간·버그 버퍼로 계산한 현실 추정이다. 확정 날짜가 아니며, 사용자 작업 시간이 정해지면 다시 좁힌다.

> 핵심 결론(먼저): Codex의 코딩 속도는 병목이 아니다. **병목은 사람 검수·승인 처리량과 Unity 검증 시간이다.** 아래 일정은 전부 이 전제를 반영한다.

## 1. 일정 산정 전제

### 현재 확인된 프로젝트 상태 (2026-07-09)

- Day/Night 루프, 낮 채집(5포인트), 상점 진열·가격·구매, 정산, 마을 변화 1종(VC-001A)까지 **한 바퀴 도는 상태**. → MVP Stabilization의 상당 부분이 이미 구현됨.
- Git clean baseline 확보(커밋 `8e79c0c`).
- 스크립트 ~90개, 에디터 검증기 ~20개 존재.

### 사용 가능한 정보

- `TASK_QUEUE.md` 85개 작업, 난이도·선행관계·사람승인 표기.
- 기존 검증기(`PA_DayNightShopLoopValidator` 등)로 자동 회귀 가능.

### 미확정 정보 (DECISION_REQUIRED)

- 졸업 발표 Demo Lock 날짜: **미정** → §6 역산표로 대응.
- Vertical Slice 두 번째 낮 활동: **미정** → 임시 기본값 낚시.
- 보류 검증기 실행 방식: **미정** → 임시 기본값 Editor 닫고 D3D11 batchmode.
- 주간 작업 가능 시간: **미정** → §5 3시나리오로 대응.

### 임시 가정

- Codex 1작업 = "구현 + 자체 검증 + 문서 기록" 한 사이클.
- 사람 승인 작업(21개)은 코딩 시간보다 **대기·검토 지연**이 크다 → 버퍼에 반영.
- Full Game(Phase 9)의 큐는 **시작점**이며, 실제 완성은 큐의 3~5배 작업이 더 필요하다.

## 4. 마일스톤 정의

### Milestone 1. MVP Stabilization
현재 흐름이 안 깨지고 검증기로 회귀 확인되는 상태. **큐: Task 001–016.**

### Milestone 2. Graduation Demo Milestone
5분 시연 루트(낮 채집/낚시→진열/가격→밤 영업→정산→마을 변화)가 안정. **큐: Task 001–045 핵심 + 061–067**(깊은 Trend/Save 일부 생략 가능).

### Milestone 3. Vertical Slice
1일 완전 루프(낮→재고→밤→통계→다음날 마을 변화)가 저장까지 성립. **큐: Task 001–072.**

### Milestone 4. Full Game Completion
출시 후보 구조. **큐: Task 001–085 + 이후 확장**(큐는 시작점, 실제 3~5배).

## 5. 3가지 개발 시나리오

> 계산법: 시나리오별 "하루 작업 수 × 주당 일수 = 주당 작업 수"로 누적 작업 수를 나누고 버퍼를 곱함. 누적 작업 수 — MVP 16, Grad ~52, Slice 72, Full(큐) 85.

## 7. Codex 운영 속도 정책

- **하루 권장 작업 수**: 저강도 1~2 / 집중 3~5 / 크런치 5~8(품질 위험).
- **3~5개 작업마다** `HANDOFF_FOR_CODEX.md` 갱신(`CODEX_HANDOFF_PROMPT`).
- **5~10개 작업마다** 사람 검수(변경 누적 리뷰 + 커밋).
- 큰 기능(L/XL) 전에는 `CODEX_TASK_SPLIT_PROMPT`로 먼저 쪼갠다.
- **실패 2회 이상이면 BUGFIX 루프 중단** 후 사람 판단(`VERIFICATION_RULES.md` §3).
- Demo Lock 이후 새 기능 금지.
- Full Game 단계에서는 **Vertical Slice 회귀 통과**를 조건으로만 확장(`CODEX_FULL_GAME_EXPANSION_PROMPT`).

## 9. 최종 추천 일정

- **최소 안전 목표**: MVP Stabilization 완료 + 현재 데모 5분 루트 안정화 (Scenario A ~3주 / B ~1주).
- **현실적인 목표**: Graduation Demo Milestone — 낚시 최소 포함 5분 시연 (Scenario A ~9~10주 / B ~3주).
- **욕심내도 되는 목표**: Vertical Slice — 저장까지 1일 완전 루프 (Scenario A ~13주 / B ~4~5주).
- **지금 포기해야 할 범위**: Phase 9 대형 확장(계절/지역/추가 콘텐츠), 멀티플레이, 광질/농사 심화.
- **나중으로 미뤄도 되는 범위**: 보조 루프(캠핑/가구), 이벤트/축제, 밸런스 세밀 조정, 사운드 전면.
- **절대 포기 금지 핵심 재미**: SCOPE §8 5가지(위 §8 재기재).

## 10. Fable 최종 판단

현재 구조는 기존 시스템이 이미 한 바퀴 도는 안정 지반이 있어, **Codex 반복 작업만으로 Vertical Slice(Milestone 3)까지는 현실적으로 도달 가능**하다. 그 이상(Full Game Completion)은 Codex만으로는 품질·밸런스·재미에서 한계가 있어 사람/고급 모델 개입이 필수다.

| 구분 | 해당 작업 |
|---|---|
| **Codex만으로 충분** | XS/S 대부분 — 조사·문서(Task 001~003,005~007,032,036 등), 표시/로그 추가(018,019,022,028), 검증기 실행(026,035), 원인 명확한 버그 1개 수정 |
| **Codex + 사람 승인** | 저장 스키마(055,057), 밸런스(033,080), 씬/성장(076,077), 1일 루프 통합(068), NPC 행동(050) |
| **Fable/고급 모델 검수 필요** | 여러 시스템 연결 설계(047,054,070,073,079), 마을 변화 로직(048,049), Phase 9 확장 설계, 검증 2회 실패 문제 |
| **사용자가 직접 방향 결정** | Demo Lock 날짜, 두 번째 낮 활동 확정, Full Game 범위 취사선택, 재미·가독성·출시 판정(016,067,071,072,082,085) |

권장 운영: **Scenario B(집중)**를 기본으로, 사람 검수를 5~10작업마다 반드시 끼워 슬롭을 차단. Graduation Demo까지는 Codex 주도, Vertical Slice의 저장·통합부터는 Fable/사람 검수 비중을 높인다.

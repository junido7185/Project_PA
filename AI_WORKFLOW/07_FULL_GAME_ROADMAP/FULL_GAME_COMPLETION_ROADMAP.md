# FULL_GAME_COMPLETION_ROADMAP — 완성 게임 로드맵

작성: 2026-07-09
전제: 목표는 프로토타입이 아니라 **완성 게임**. 각 단계는 이전 단계의 결과를 갈아엎지 않고 위에 쌓는다.
범위 정의: `../01_IDENTITY/PROJECT_PA_SCOPE.md`. 기존 백로그: `PROJECT_PA_FULL_GAME_BACKLOG.md` (CN/FG 항목), `PROJECT_PA_MASTER_DEVELOPMENT_PLAN.md` (10/30시간 구조).

## 단계 개요

```
Stage 0. MVP Stabilization   ← 현재 위치
Stage 1. Vertical Slice
Stage 2. Graduation Demo Lock  (졸업 발표 마일스톤)
Stage 3. Alpha                 (시스템 전부 존재)
Stage 4. Beta                  (콘텐츠·밸런스 완성)
Stage 5. Release Candidate     (안정화·출시 준비)
```

각 단계 완료 판정은 **사람**이 한다. AI는 완료 조건 증거를 제출할 뿐이다.

## Stage 0 — MVP Stabilization (현재)

목표: "다시 안 갈아엎는" 첫 안정 지반. 낮 채집 → 진열/가격 → 밤 영업 → 정산 → 마을 변화 1종의 한 바퀴가 검증된 상태.

| 필요한 것 | 상태 |
|---|---|
| Day/Night 루프 + 영업 게이트 + 정산 | 구현됨 |
| 마을 변화 신호 1종 (VC-001A) | 구현됨, **미커밋** |
| 배치 검증기 전체 통과 재확인 | 보류 (Editor 열림) |
| 1920x1080 수동 가독성 확인 | 사람 대기 |
| 클린 Git baseline (체크포인트 커밋) | 사람 대기 |
| 저장 v8 왕복 확인 | 필요 |

- **Codex에게 맡길 수 있는 것**: 검증기 실행(Editor 닫힌 상태), 저장 왕복 테스트, 문서 정리 실행(클린 baseline 후), 버그 수정(범위 한정).
- **사람이 판단해야 하는 것**: 체크포인트 커밋 승인, Game view 가독성, VC-001A 시각 변화의 느낌 승인.

## Stage 1 — Vertical Slice

목표: Day 1~7 한 주가 "완성 게임의 재미 축소판"으로 성립 (SCOPE §3).

| 필요한 시스템 | 근거 백로그 |
|---|---|
| 낮 활동 다양화 (채집 외 1계열 이상 실장: 낚시/광질/농사 중 택1) | IL-002 |
| 가공 1체인 (원자재→가공품 가치 상승 체감) | FG 계열, Docs/02 §1.1 Process 3.0 |
| 손님 성향 차이가 구매 결과로 읽힘 (기존 SPY 레이어 심화) | SPY-002/003 |
| 마을 변화 신호 2~3종 (카테고리별 차별화) | VC-001 확장 |
| 가게 확장 1단계 (슬롯/시설) | CN/FG 계열 |
| 저장으로 주차 이어하기 | 저장 v8+ |

- **Codex 가능**: 각 시스템의 사이드카식 구현, 검증기 추가, 기존 데이터 확장.
- **사람 판단**: 어떤 낮 활동을 먼저 실장할지, 밸런스 초기값, 마을 변화의 시각 방향.

## Stage 2 — Graduation Demo Lock (졸업 발표 마일스톤)

목표: 발표에서 안정적으로 보여줄 시연 고정. **Vertical Slice의 안정 부분집합**을 잠근다.

| 필요한 것 |
|---|
| 시연 루트 확정 + `PA_FinalDemoRouteValidator` 통과 고정 |
| Windows 빌드 + 실행 리허설 + 백업 녹화본 |
| 발표 자료 갱신 (기존 `Docs/발표_개발현황보고서.md` 계열) |
| 시연 중 금지 변경 기간(코드 프리즈) 설정 |

- **Codex 가능**: 빌드 생성, 검증기 통과 확인, 발표용 문서 초안.
- **사람 판단**: 시연 시나리오, 프리즈 시점, 발표 내용.

## Stage 3 — Alpha

목표: 완성 게임에 필요한 **모든 시스템이 1차 형태로 존재** (콘텐츠는 부족해도 됨).

| 필요한 시스템 |
|---|
| 낮 활동 4계열 전부 + 주민 의뢰 |
| 가공 체인 복수 + 전문가 NPC |
| 관광객 손님 계층 + 평판/단골 기초 |
| 가게 확장 2단계+ / 시설 해금 트리 |
| NPC 고용/자동화 1차 (반복 노동 위임) |
| 마을 변화 시스템화 (카테고리→풍경/행동/시설 매핑) |
| 계절 또는 주간 수요 변화 1차 |

- **Codex 가능**: 시스템 골격 구현, 데이터 스키마 추가 확장, 검증기 동반 작성.
- **사람 판단**: 새 게임플레이 시스템 승인(각각), 저장 스키마 확장 승인, 재미 판정.

## Stage 4 — Beta

목표: 콘텐츠·밸런스·연출이 채워져 "게임으로 완성"된 상태.

- 아이템/NPC/시설 콘텐츠 목표 수량 충족 (기준: `Docs/기능_명세서.md` 재조정판)
- 밸런스 패스 (가격/수요/성장 곡선)
- 아트 일관성 패스 (Tripo3D/Nano Banana 파이프라인, `Docs/08`)
- 사운드 (BGM/SFX)
- 온보딩/튜토리얼 정리
- 장기 플레이 QA (Day 30+ 세이브 내구성)

- **Codex 가능**: 데이터 입력 보조, 회귀 검증, 버그 수정, 통계 수집 도구.
- **사람 판단**: 밸런스 확정, 아트 승인, 콘텐츠 컷 결정.

## Stage 5 — Release Candidate

목표: 배포 가능한 안정 빌드.

- 크래시 제로 확인 (장시간 플레이/저사양 확인)
- 빌드 파이프라인 고정 + 버전 태깅
- 세이브 호환성 최종 확인
- 스토어/배포 요건 (사람 주도)

- **Codex 가능**: 회귀 테스트 자동화, 빌드 스크립트 정리, 문서 최종화.
- **사람 판단**: 출시 판정 전부.

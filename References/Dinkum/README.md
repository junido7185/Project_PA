# Project P.A. — 딩컴 실물 레퍼런스

2026-10-09. 사용자가 직접 실행한 딩컴에서 캡처한 원본 16장과 관찰 기준이다. 이 ZIP를 Project_PA 루트에 풀면 References/Dinkum/ 아래에 자료가 놓인다. 이미 구성한 제작 환경과 현재 작업을 이어받아 사용한다.

## 현재 목표

사용자는 기존 약 5분 플레이가 구현됐고 발표 가능한 상태라고 밝혔다. 이제 실제 화면과 플레이를 본 사람이 “이 사람은 딩컴 같은 3D 생활 게임을 구현할 수 있겠구나”라고 느낄 만큼 월드·동작·아이템·소품·UI·연출의 완성도를 높인다. 기존 플레이는 회귀 확인 기준이다. 신규 성장 고리·Tier·캠페인 확장·플레이 시간 제한을 현재 품질 제작의 선행 조건으로 삼지 않는다.

현재 제작 총괄이 이 문서와 이미지를 읽고 각 작업자에게 관련 원본 파일을 전달한다. 사용자 선택에 따른 Codex→Claude 총괄 인계가 진행 중이면 현재 변경·작업 소유권을 이어받는다. 레퍼런스 도입 때문에 환경 구성이나 역할 설정을 처음부터 반복하지 않는다. live Unity 편집·입력은 현재 통합 담당 한 세션만 수행한다.

## 지금 할 일

1. 이 폴더의 원본 이미지를 실제로 열어 본다. 파일명·설명만 읽고 시각 자료를 확인했다고 보고하지 않는다. Builder와 독립 Critic가 각각 같은 레퍼런스에 접근할 수 있게 한다.
2. 현재 P.A.의 해안·숲·바위가 있는 동선·캐릭터·가방 창을 캡처한다. 로컬 최신 변경을 유지하며, 캡처와 이미지 파일 경로를 연결한다.
3. 월드에서 가장 크게 다른 부분을 근거와 함께 세 가지로 정하고 실제 제작한다. 첫 비교 구역은 해안과 인접 식생이다. 지형·물·식생·조명·카메라를 한 화면에서 맞춘다.
4. 현재 사용 중인 자산·도구를 조사해 필요한 모델·텍스처·재질·셰이더·배치·애니메이션을 제작하거나 교체한다. 기존 자산 유지나 코드 파일만 수정 같은 인위적 제한을 두지 않는다. 원본 데이터와 기존 연결은 보존한다.
5. 같은 P.A. 시점·해상도·시간대의 전후 화면과 보행 영상으로 비교한다. Critic는 구현자의 해명·자기 점수를 받지 않고 결과와 참고 자료로 큰 차이를 지적한다. 수정·재실행·독립 검증 후 관련 공간으로 확장하고 다음 품질 단계로 이어간다.

첫 납품은 실제 Unity의 전후 화면과 바뀐 자산·씬 연결이다. 보고서, 새 규칙서, CLI 호출 성공, 컴파일 성공만으로 시각 품질 개선을 완료 처리하지 않는다.

## 이미지에서 도출한 제작 기준

이 항목은 화면 관찰을 바탕으로 한 제작 목표다. 딩컴의 내부 코드·셰이더·폴리곤 수·카메라 수치를 확인했다는 뜻이 아니다.

- 공간: 흙·모래·풀과 높낮이가 서로 구분되고, 캐릭터 크기에 맞는 나무·바위·도구가 같은 화면에 놓인다. 카메라 각도와 거리까지 함께 맞춘다. 특정 지형 내부 구조를 억지로 복제하기보다 실제 플레이 시점의 형태와 경계를 제작 기준으로 쓴다.
- 바다: 모래 해안과 물이 연결되고, 물 아래 바위와 식물이 보이며, 표면 무늬와 깊이에 따른 색 차이가 공간을 만든다. 물 평면의 색만 바꾸고 완료 처리하지 않는다. 실제 셰이더와 지형·수중 자산의 조합으로 구현하고 각도 변화에서도 확인한다.
- 식생: 나무 수관·풀 덩어리·자원 바위가 읽히는 형태를 갖고, 밀집한 곳과 이동할 빈 공간이 함께 있다. 자산 수만 늘리기보다 크기·색·군집·바닥 재질·그림자를 조정한다. 동작과 가독성을 확인한 후 성능도 측정한다.
- 캐릭터와 도구: 캐릭터 비례, 옷과 머리의 형태, 도구 크기와 손 위치가 어울린다. 근접 화면과 일반 플레이 화면에서 모두 확인한다. 새 모델·리깅·클립이 필요하면 실제 Unity용 자산으로 제작·연결한다.
- UI와 소품: 패널의 색·테두리·글자·여백·슬롯·아이콘이 같은 규칙을 따른다. 인벤토리에서 아이템을 식별하고, 세계 내 모델에서도 같은 물건으로 알아볼 수 있게 만든다. P.A.의 가구와 생활 소품은 동물의 숲 참고도 같은 표현 기준 안에 통합할 수 있다.

## 모션을 확인하는 방법

정지 이미지로 손 위치·도구 크기·동작 중 한 자세는 볼 수 있다. 이동 속도·발 접지·휘두름의 시간·명중 순간·조작 복귀·소리는 정지 이미지로 검증하지 않는다.

사용자는 자신의 Steam에 있는 딩컴을 직접 실행해 참고 확인하는 방법도 허용했다. 로컬 제작 총괄은 실제 사용 가능한 창 제어·입력·영상 캡처 도구를 확인하고, 딩컴이 이미 실행 중이면 그 창을 재사용한다. 필요한 경우 설치된 게임을 Steam에서 실행한다. 현재 Unity 작업을 안정된 상태로 보존한 뒤 딩컴의 PID와 전경 창을 확인해 입력·캡처를 그 창에만 보낸다. 기존 게임 저장은 보호하고 관찰·촬영 목적의 플레이를 수행한다.

우선 정상 속도 영상으로 보행·정지·회전, 도구 들기와 휘두르기, 타격·자원 반응, 물가 이동, 가방 열기·선택·툴팁·닫기를 확인한다. 필요한 구간만 기록하고 캡처 파일과 관찰 항목을 연결한다. 실제 도구가 게임 입력을 지원하지 않으면 해당 구간은 미검증으로 남기고, 아래 공개 자료에서 볼 수 있는 구간을 찾아 제작을 계속한다. 게임 실행 파일을 찾았다는 사실만으로 플레이를 확인했다고 보고하지 않는다.
